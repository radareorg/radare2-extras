# uSIP (MD32 family, VLIW packet variant) — ISA table notes for the `usip` CPU mode

Reference for the table format, the constraint semantics and the packet model behind the `usip` CPU mode.  Everything
in it is implemented by `usip_decode.c` (packet model), `tools/gen_usip_tables.py` (table) and `arch_md32.c` (RAnalOp
mapping); see README.md "uSIP mode" for the user-facing description.  Files:

| file | what |
|---|---|
| `isa/usip_isa.json` | the machine-readable table: `meta`, `structure` (packet model incl. the layout order, the K-tie cascade, the prefix, grammar and rename rules, registers, CSRs, system ops, I/O ports, conditions incl. the 48-bit condition table and the S0F1 tail variants, displacement and immediate formulas, field types, context rules) and the ORDERED list `forms` |
| `usip_opcodes.h` | the same forms as a C table (`UsipOpcode usip_opcodes[]`), generated by `tools/gen_usip_tables.py`, plus `usip_never_tail[]`, `usip_never_head_with_tail[]`, `usip_c48_table[]`, `usip_br0_cells[]` / `usip_br0_cells_weak[]`, `usip_c48sym_table[]`, `usip_value_sets[]` and the `rename_from` lists |
| `usip_decode.c` | the packet decoder (`parse_group`, `group_parses`, `decode_asg`, `score`, `fviol`, `parse_packet`, `apply_renames`, `decide_ties`) |

## 1. The packet model

The earlier `usip_decode()` read one 16-bit halfword and, when bit 15 was 0, paired it with the next halfword. That is
wrong in general: **the unit is the 16-bit halfword and the instruction stream is a VLIW packet stream.**

1. **Unit scan.** Read halfwords (big-endian) from the packet start. A packet = consecutive units up to and
   including the first unit with **bit 15 = 1** (max 8 units). Packets start at `addr % 4 == 2` as often as at
   `addr % 4 == 0`: never assume 32-bit words. Branch targets are packet starts.
2. **Heads and tails.** Inside a packet, a unit with bit 15 = 0 is either a *head* (first unit of an instruction) or
   a *tail* (second/third unit of a 32/48-bit instruction). Instructions are **head + 0, 1 or 2 tails**, 16/32/48 bits
   (64 bits only for the `bcc64` prefix forms: head + `1e0d` + U1 + T). A head without a tail is a 16-bit op "with the
   packet still open" (its bit 15 is 0 but it is decoded like the bit-15 = 1 form; most 16-bit entries of the table mask
   bit 15 out, the stand-alone *closer* forms keep it).
3. **Prefix forms.** Before anything else, if the packet opens with the three (four) units of a `bcc48` (`bcc64`) entry
   (`USIP_F_PREFIX`: U0 op b-f with F = 1 (F = 0 + `1e0d` for the 64-bit twin), U1 `[0][1][m'h'][rrr'x'][00000000]`, T
   `[S][1][00][d12]`) AND the target `packet start + 2·sext12(d12)` is a packet start of the same function (≠ the packet
   itself), those units are ONE instruction and the rest of the packet is its delay slot (parsed as an independent packet
   without control flow). A failing guard means the entry is simply not taken (normal layout, never `.word`). The absolute
   `call.abs/b.abs` prefix (`x008 + hi + lo`, rule R) is unchanged. `5e0d` as U0 (`bgt.l r0, #255`) and `1e0d` as the
   bcc64 extension unit are matched here, before the never-tail rule of item 4.
4. **Layout (head/tail pairing).** Tails are not necessarily adjacent to their head: the packet is *heads first,
   then tails*, and the tails are dealt **round-robin** among the heads that take tails, in head order (`S S O O` =
   two 32-bit instructions interleaved). A packet may also be a sequence of *groups*, each laid out that way
   (one-instruction groups = contiguous layout: `b dest ‖ delay-slot ops`). No bit selects the layout. The decoder
   enumerates every group split and every head/tail assignment allowed by the table (a head may take a tail iff some
   non-context, non-rename form matches head+tail; a head may stand alone unless it is in `structure.packet.must_pair`;
   `ret/save/restore` never take tails; **the units of `usip_never_tail[]` (`5e0d`) are never a tail and the heads of
   `usip_never_head_with_tail[]` (`5e0d`, `1e0d`) never take one**; **a 48-bit op 0 head also takes `hi + lo` when
   `head[13:9]:hi[12:0]:lo[13:0]` is one of the values of `usip_c48_table[]`**, the non-canonical 48-bit constants
   admitted by value — in the partial head:hi admission some table value must share the upper 18 bits), discards,
   inside a group, the assignments with more bare heads that have no named 16-bit reading, adds the explicit candidates
   (`[head][op16][F' = 0 tail]` for 3 units — not for a head that never takes a tail —, **H H T T** =
   `[h0][h1][t0 S=0][t1 S=1]` with two named ld/st for 4 units, also with tt = 11 tails (`ld.bu` / `st.b`) and the
   bit-field pair `[op 7][op 7][tt = 01 S = 0][tt = 01 S = 1]`, and loopcand, R-brHHTT, R-b111pre and R-b111ctl of
   item 15) and ranks the readings with the **prior-free total
   order** (`structure.packet.layout_order`): `(s0, I, Fv, −A, K)` ascending, where `s0` = unknown units (kind `other`:
   1 per unit; kind `fmt`: 1 per instruction) + the tie-break penalties of `structure.packet.tie_breaks` (R7 credit, O
   syllables, loose `4000`, alignment except `f12 ≡ 3 ≥ 0xf00` and except `f12 ≡ 2` in the H H T T / H H T T C layout
   (P2W), the add relabel, 1dX6, `.hi/.hilo`, the fam48 r14/r15 destination, the store-of-immediate triples, the
   identical-units rule of 4-unit packets, the mfcsr pair, the validated-guard −0.5, **callin**: +1.5 for a relative
   `call` whose target is strictly inside a known function, **P2H**: the odd half-word offset is not penalised in
   H H T T / H H T T C except `f12 = 0x001` with base sp, **R-lr16**: +0.5 for a 16-bit `ld/st.b|bu|h r15, [rA]` in a
   2-unit packet, **R-align48**: +0.5 for a formed 48-bit hi(1010) ld/st trio whose address is misaligned,
   **R-c48sym**: +0.5 for a reading that leaves a 48-bit-family head without tails while a later free hi(1010) + lo of
   the packet encode an address of `usip_c48sym_table[]`, and the rules of item 15: **R-waw**, **al1**, **R-bsnext**,
   **sat40 H H T T**, **rf0dpen**, the P2W / P2H exemption of the H H T T prefix), `I` = number of instructions, `Fv` =
   heads with a tail
   whose adjacency contradicts the **F pattern** (head F = 0 and next unit bit 14 = 1 ⇒ adjacent tail, otherwise
   deferred), `−A` = minus the number of adjacent tails, `K` = the sorted tuple of `(head index, (tail indices…))`
   (smallest first). Readings tied on `(s0, I, Fv, −A)` go through the **K-tie cascade** (item 12) and, when it does
   not decide, are the **ambiguous** packets (K decides) unless the tied readings are identical. No learned prior and
   no group count take part. Rule **R0**: the final closer (bit 15 = 1) may be a one-unit group of its own even when it
   has no named 16-bit reading. Rule **R7**: a bare first-slot unit with bit 15 = 0 of the slot family (or of the `lea?`
   shape with rA ≠ r14 when no other instruction of the packet has a tail) counts as a named unit when every other
   instruction of the packet is named, and is printed through the context forms `ldslot_S0`/`stslot_S0`/`lea_sp_S0`.
   When no group parse exists a greedy fallback pairs each head with the next free unit if some form matches.
5. **Slot 0.** Only the first unit of a packet can be control flow (branches, `call/b`, `loop`, `loop #N`,
   `bcc48/bcc64`, 16-bit branches incl. `call.s` with bit 15 = 0, `beqz.d/bnez.d` with F = S = 0, `call.abs/b.abs`,
   the `b<cond>.d` with the `[0][1][tt]` tail at +2: the S0F1 cells, the `b<cond>.d` with head F = 0 of the R-br0
   cells (tail `[0][1][tt]` at +1 or +2, `USIP_C_BR0_CELLS`), `ret.s.d`, `loop.b1?`, `bz.s` with bit 3 = 0); forms
   flagged `USIP_F_SLOT0` must not be matched elsewhere. The 32-bit `ret` (`40ff c000`), `ret?`, `jr rB`, `call rB` and
   the `sys` twins with F = S = 0 are NOT slot-0 forms. Tail adjacency of the control forms (`USIP_F_ADJCTRL`: +1
   with S = 1 or +2 with S = 0; `USIP_F_ADJ2`: exactly +2 for the F' = 0 control tails, for the S0F1 branch tails AND
   for `loop #N` with F = 1, S = 0 — at +1 that one is two 16-bit ops, not `.word`; `loop_F0` also at +2 with S = 1).
   **Target guards**
   (`cons = "guard:target_*"`): for 32-bit forms evaluated AFTER the mask match, a failure makes the pair `.word` (no
   fall-through; the op C compare-and-branch cell, `bnez.d` with F = S = 0, leaves a `.dsp` pair: the pair is unnamed
   data either way, the name is the only difference) unless the entry carries `USIP_F_GUARDFT` (the F = S = 0
   `b<cond>.d` cells, `bne.d #-1`, the R-br0 cells: the next entry of the cell is tried and, when none is left, the two
   units are 16-bit ops — R-tgt, item 13: the known target is a filter, never a partition); for the 16-bit `call_s_S0`
   and the open `b.s` (`b_s_open`: a packet start of the same function or a function start) a failure falls through;
   for the prefix forms a failure means "not taken". The near `b` (`b_near`) needs a packet start of any function of
   the image or a function start (`guard:target_packet_start_any_or_function_start`), the hardware loops with the
   F' = 1 tail (`loop`, `loop …, x16`, their `?ss=N` twins) a packet start of the same function.
6. **Deferred tails and undo.** `USIP_F_ADJDEF` (`st.h` with the F' = 0 tail, R-st1h): the tail must be at +2 or
   farther; an adjacent tail undoes the pair into two 16-bit ops. `guard:head_not_validated_bs`: in the first slot,
   when the head is a 16-bit `b.s` shape (`5cX1/7cX1`, not m = 0 with d6 = 0) whose target is a packet start of the same
   function, the pair is undone (the `b.s` wins). `USIP_F_ADJ1` (immediate set-on-compare, `add_FS12`, `seq/slt` of
   op 6): a farther tail undoes the pair. `USIP_F_ADJ2` on a ld/st entry (`mem_ld_b_t4_F1S0`, `mem_st_h_t6_F1S0`,
   R-op1fs: the F ≠ S `ld.b` / `st.h` of op 1): the tail must be exactly at +2; at any other distance the pair is
   undone into two 16-bit ops (not `.word`).
7. **Position selectors.** Constraints `head_index == n` / `head_pos_ge n` (unit index of the head inside the packet)
   and `packet_len >= n` select the identical-bit cells by position: `mfacc_q_C_k2` (k ≥ 2), `cellE_st_h_q_k1` /
   `cellE_add_q_k2`; `ld_w16_A_k0` (k = 0) and `lsl16_F1_S0_k1_q` (k ≥ 1) are post-layout renames (item 11). Entries
   whose deferred constraints fail FALL THROUGH to the next entry of the same cell. `ctx:not_ext_of_op67`
   (`add_FS1_rot12_odd`) needs the first unit of the packet. `ldslot_S0_m1` / `stslot_S0_m1` (R-slotm1: the m = 1
   slots of op 4/8/c, k ≥ 32) are R7 forms that also need `ctx:rest_named_no_q` (every other instruction named, none
   with a `?`).
8. **Context forms (`USIP_F_CTX`).** `bz_s_P4`, `bz_s_P5` (R-bzs5: a first-slot `4X?5/6X?5` unit, rA not sp/LR,
   whose best reading is a bare unnamed unit is `bz.s rA, dest` with the rest of the packet as its delay slot:
   unconditionally in a 2-unit packet, in a longer one only with the target validated as a packet start of the same
   function), `bz_s_P4_u4` / `bz_s_P4_u3` (the same unit opening a packet of exactly 4 / 3 units, item 15),
   `movi6_dsbr` (R-movi6d, item 15), `ldslot_S0/stslot_S0/lea_sp_S0` and the m = 1 twins (R7 / R-slotm1),
   `ldslot_split/stslot_split` (the
   two halves of an `.op8?`/`.op8.t?` pair of slot-family units, context rule `op8_slot_split`), the `hhtt_*` ld/st
   forms with F ≠ S and the `b111_*` ld.bu / st.b forms with F ≠ S or F = S = 0 (only inside the H H T T candidate:
   `USIP_F_HHTT`, `ctx:b111_layout`), the `b111_*_F1S1` forms (`USIP_F_B111`: the 2-unit head + tail packet with a
   named 16-bit tail, and H H T T), the bit-field pair `bfpair_*` (`ctx:bfpair`, `bf_valid`), the `f0ctx` group
   `hhttF0_*` / `rf0d_*` (`USIP_F_F0CTX`, `ctx:hhtt_second_head` / `ctx:f0d_triple`: tried when the op 0 +
   `[S][0][01|10]` pair at +2 reads `.word`; after an `rf0d_*` reading the unit between head and tail is re-read with
   the first-slot 16-bit cell when that gives a named, non-control op that does not write r14: context rule
   `f0d_middle_unit`) and `hi1010_loose` (`.hi`): a lone unit with bits 12:9 = 1010 is `.hi` (and the next `.hword`
   `.lo`) only when a head of the 48-bit family precedes it in the packet (context rule `hi_lo_fam_before`); otherwise
   it is an ordinary 16-bit head with base/source r10 (**H1**: a hi(1010)-shaped unit is a `hi` syllable only inside a
   formed 48-bit instruction; the table has no `not_hi1010` constraints and no `.hi/.hilo` pair entries, and the
   parser no longer forces the hi(1010) decode of such heads in 4-unit packets).
9. **Delay slot = the rest of the packet.** When the control instruction does not close the packet (`call`/`b` with
   an S = 0 tail, `b<cond>.d` incl. the S0F1 forms, `b<cond>.l` with S = 0 on T, `ret.d`, `b.s` with bit 15 = 0,
   `call rB`, `call.abs`), every other unit of the packet executes before the transfer (on both paths). For radare2 this
   means `op->delay` = number of remaining ops in the packet, and the branch instruction's `size` covers only its own
   units while the fall-through address of the packet is the next packet.
10. **Hardware loops.** `loop rX, last=pc+disp12`, `loop #N, last=pc+disp12` (`USIP_A_LOOPN`: N = head bits 13:5 =
    `m:h:rrr:x:B[3:1]`, 0..511, the collected field as is; the heads with h = 1 (N ≥ 128) and with m = 1 (N ≥ 256,
    printed `loop #N?`) are loops too, and so is the head whose F' = 0 tail sits exactly at +2 (`loop_imm_*_F1_Fp0`,
    R-loopA: the middle unit is a 16-bit op of the packet, at any other distance the pair is `.word`); the explicit
    layout candidate **loopcand** adds the `[loop head][op16][tail at +2]` reading that the group grammar drops when
    the middle unit has no named 16-bit reading, item 15), `loop rX, last=…, x16` (the head with B = 1: the packet at
    the loop end crosses a 16-byte line, a fetch hint that leaves the loop semantics unchanged; formerly `loop.b1?`)
    and the `?ss=N` twins (`loop r<rrr>?ss=N`, `loop r<rrr>?ss=N, x16` for ss ≥ 2): `last` is the
    address of the LAST instruction of the body (inclusive); the body is the following 1-16 instructions; `last` must
    be a packet start of the same function and ≠ pc. `de0d` (`nop.ctl` with S = 1) closes most hardware-loop bodies.
11. **Post-layout renames (`USIP_F_RENAME`).** Forty-one entries (`nop_ctl`, `lsl16_S0`, `lsl16_F1_c`,
    `lsl16_F1_S0_k1_q`, `sext16_F1_c`, `sext16_F1_S0_q`, `zext16_F1_c`, `zext16_F1_S0_q`, `addi32_cop`, `ld_w16_A_k0`,
    `x1e0_ld_w_q`, `x1e0_ld_h`, `x1e0_ld_hu`, `x1e0F0_add_q`, `x1e0F0_ld_h_q`, `x1e0F0_ld_hu_q` (R-1eX0F0: the `.1eX0`
    head with the F' = 0 tail), `op7e_0_bset_r`, `op7e_6_bext_r`, `ldF0_q_t1_adj`, `ldF0_q_t2_adj`, `ld_h_Fp0`,
    `ld_hu_Fp0`, `x3eX0_q`, the BF_SEL cells `bfsel_fup`, `bfsel_fup_q`, `bfsel_fxtu`, `bfsel_fxtu_q`, `bfsel_fxts_q`
    from `.bf?` with `ctx:bf_dst_not_written` — no other WAW-kind instruction of the packet writes rB(!x) —,
    `negq_ld_w_c1/c3`, `negq_st_w_c1/c3` (`ld.w?` / `st.w?`), `spfix_add_sp` (from `ld.w`), `stimmsp_st_w_sp`
    (`st.w [sp], #imm` from `mov32` / `st.w?`, R-stimmsp), the six split entries `stslot_F0`, `stslot_F0_q`,
    `stslot_S0_pos1`, `ldslot_S0_pos1_q`, `ldslot_S3_F0`, `stslot_S3_F0` (`USIP_F_SPLIT`) and the fusion entry
    `op72_q` (`USIP_F_FUSE`)) are NEVER used while pairing or scoring (the layout is decided with the underlying
    reading: `.ctl15`/`.hword`, `.sub?`, `.1eX0`, `.word`, `.7e`, `mov32`/`add`). Once the layout is decided, for
    each instruction the rename entries of its width are tried in table order: mask over the gathered units,
    `rename_from` containing the current reading (a mnemonic, or `@kind` for every reading of that kind), the other
    constraints (`head_pos_ge 1`, `instr_index n` — the position of the INSTRUCTION inside the decoded packet, not
    the unit index —, `tail_adjacent == true/false`, `ctx:cop_rA_in_packet`, `ctx:not_c48_lo_follows`,
    `u16 in [...]`) → the instruction takes the entry's mnemonic / kind / format; the score is untouched. The split
    and the fusion entries are skipped by this pass: the split pass and the fusion of item 14 apply them by index.
    `sub r14, #imm` (frame allocation) is no longer a rename but the parser form `spsub_sub_sp` (R-spsub, any
    F / F').
12. **K-tie cascade.** For each packet whose readings tied on `(s0, I, Fv, −A)`: `dedup` (identical multisets of
    instruction texts → the K reading), `nowaw` (exactly one reading without a double register write → chosen; all
    with one → no decision), `du2` (a differential use-definition score over a window of eight packets before and
    after the packet, decision margin 1: only the registers whose role differs between the tied readings score — in
    the forward direction a use, an argument, a dead value or a clobber of the register; in the backward direction a
    definition, a return value, a live or a clobbered register); the chosen reading replaces the K reading. A fourth
    step, a vote of the debug line table over other packets of the same source line, is not reproducible from the
    bytes and is left to K. A decoder without any function context reproduces the bare K key; the cascade is a
    tie-break improvement, not an admission rule. §7 describes what the plugin can see.
13. **Address views (R-img) and the target filter (R-tgt).** Every function is validated with the packet starts,
    function starts and ranges of its own image: a function table that holds two overlapping copies of the same code
    (a routine mapped twice, each copy with its own ranges) must carry the image, or a merged table validates targets
    of the other copy and rejects branches with the wrong function limits. A disassembler that works on one image at
    a time has a single view by construction, so the plugin has nothing to do for R-img. R-tgt: a known target is a
    filter, never a partition. The plugin asks the caller for packet starts and function starts (§6); a known target
    that is not one rejects the reading (fall-through to the next entry of the cell for the `USIP_F_GUARDFT` entries,
    the next 16-bit entry for the open `b.s`, `.word` for the near `b` and the loops), an unknown one keeps the
    reading unverified for the forms whose guard is a validation filter.
14. **Post-layout splits and fusion of the slot family.** After the layout (the score is untouched, only the names
    change) the slot family is re-read. First **S3**: a bare `.hword` `[0][0][1][1][rrr][x][B][o3 0 00]` (m = h = 1,
    F = 0, S = 0) in the first slot of a multi-unit packet is `ldslot rB, #k` (k = 48..63, `ldslot_S3_F0`) and a bare
    `.hword` closer `[1][0][1][1][rrr][x][B][o3 1 00]` is `stslot` (`stslot_S3_F0`). Then one pass with a **nowaw
    guardian**: **R-slot4n** (a pair read `.op4t0` / `.op4t1` / `.op4t3` whose head is op 4 with F = 0 and whose
    single tail is the next unit with S = 0, low 12 bits > 1 and not `4000`-shaped → head `stslot` / `stslot?`
    (k = m:h:rrr:o3, the `?` with h or m = 1: `stslot_F0` / `stslot_F0_q`) ‖ the tail's split-tail reading),
    **R-op4imm** (a pair read `.op4imm` with an op 4 head and a tail with F' = 0 and tt ∈ {00, 01}, ONLY when the
    split-tail reading is named → head F = 1 `stslot`, F = 0 `stslot` in a 2-unit packet / `stslot?` in a longer one
    (`ctx:op4imm_head_multiunit`) ‖ the tail), **S0-slot** (a bare `.hword` at INSTRUCTION position 1 with F = 1,
    S = 0, low 12 bits > 1 and (m = 0 or op ≠ 0) → `stslot` for o2 = 1 / `ldslot?` for o2 = 0: `stslot_S0_pos1` /
    `ldslot_S0_pos1_q`). The split-tail reading of a unit is: the slot family with F = 1 and S = 0 → `stslot` /
    `ldslot?`; op 4 / op c with F = 0 → `stslot(?)`; else its ordinary 16-bit reading (unnamed: kept as is in
    R-slot4n, no split in R-op4imm). The guardian returns a split whose new destination (WAW kinds; stores and `iow`
    excluded) is written by another instruction of the packet to its original entry. The units of a split pair carry
    `ctx:split_unit`. Then the generic renames (item 11) and the **fusion** `op72? rA, #k, asr#b` (`op72_q`,
    `USIP_F_FUSE`): two ADJACENT one-unit instructions whose readings are `movi rA` (head
    `[0][F][0][h][rrr][0][b][0111]`) and the 16-bit op 2 `asr? rA` with x = 1 and the same rrr (`eq_fields`) become
    ONE two-unit instruction (the `lsl` cell, x = 0, is not fused; the pair does not count as a double write).
15. **Explicit candidates, score rules and layout constraints of the 726-form table.** The explicit candidates of
    item 4 gain **loopcand** (op f head + tt = 10 tail at +1 / +2 reading `loop #N` — not `loop #N?` —, the middle
    unit a bare head; the F' = 0 tail only at +2), **R-brHHTT** (`[branch head F = 0 at 0 → 2][op 0/1 head at 1 → 3]`
    + the rest in packets of ≥ 5 units whose units 2 and 3 have S = 0 and F' = 1, when the branch reads with a
    validated target and the second pair reads ld/st), **R-b111pre** (the type-111 H H T T, both tails S = 0, as the
    PREFIX of a packet of ≥ 5 units; the rest parsed as a group) and **R-b111ctl** (`[op e head at 0 → 2][op 1 head at
    1 → 3]` in exactly 4 units, unit 2 S = 0 and F' = 1 with tt = 10/11, unit 3 S = 1: the round-robin of the type-111
    store after a control head, which the group grammar does not generate; `400e 5c01 654c f8e2` = `b ‖ st.b r0,
    [sp+0xe3]`); each is rejected by the grammar's own filters (a tail on `ret/save/restore` or on a head that never
    takes one, a unit that is never a tail) and the b111 / hhtt context forms hold inside them (`ctx:b111_layout`).
    The score (item 4) adds **R-waw** (+0.75 per register written by ≥ 2 instructions of the reading — the first
    operand of a WAW-kind instruction followed by a comma; stores excluded; the adjacent bare pair `movi rA ‖ op 2 rA,
    x = 1` of the same rrr is one instruction and does not count — the parallel-execution model), **al1** (the
    `f12 ≡ 1` / `≡ 3` (< 0xf00) word tails pay 0.8 in all: 0.3 more than a double write), **R-bsnext** (+2.5 for a
    first-slot 16-bit `b.s` whose target is exactly the next packet and not a function start: the unit is the
    `st.h/st.b` head), the **P2W / P2H exemption** when H H T T is the prefix of a ≥ 5-unit packet, **sat40 H H T T**
    (+3.0 for `[op c][op c][tail (8,c)][tail (8,c)]` not read as the pairs 0 → 2, 1 → 3), **rf0dpen** (+1.0 for the
    bare unit after an R-F0d head whose destination is written twice; **rf0dmidwaw**: that middle unit is then not
    re-read) and **R-movi6d** (the `.movi6?` closer in the delay slot of a validated branch at unit 0 counts as
    `movi rA, #simm6`: `movi6_dsbr`, `ctx:delay_slot_of_validated_branch`); scores are kept in twentieths of a unit.
    Three constraints are evaluated with the layout: **beq9sp** (`beq_imm8_d`: `any(rA ≠ 14, m = 1, tail_adjacent =
    false)` — the op 9 `beq.d` with base sp and the adjacent tail is not a branch; a failure falls to the next
    reading), the **`bgt rA, #-1` head class** (the seven op a `*_s0f1` / `*_imm8_F0` entries carry `any(m = 1,
    rA ≥ 8, x = 0, rB ≠ 15)`: with ss = 00, x = 1 and B = 15 the head only takes the adjacent S = 1 tail) and the
    **R-w6h1 loop guard** (`st_h16_f_slot0_h1`, the W6 cell `st.h rB, [r{8+rrr}]` with x = 0 and B ∈ {0, 1}, does
    not match when a `[S][0][11][d12]` tail at +1 / +2 of the packet being parsed has its end at a packet start of
    the function after the head: the unit is the head of a validated `loop r{8+rrr}`, `ctx:not_loop_reg_head`).
    **`bz.s` in 4- and 3-unit packets** (`bz_s_P4_u4`, `bz_s_P4_u3`; item 8): the same `4X?d` unit (not `5cXd` /
    `5e0d`, rA not sp) opening a packet of exactly 4 units whose best reading leaves it unnamed, with the target a
    packet start of the same function, is `bz.s rA, dest` with the rest of the packet re-parsed as its delay slot; in
    a 3-unit packet also with the target BEYOND the packet (`ctx:target_beyond_packet`) and a delay slot that does not
    write rA (`ctx:delay_slot_not_writing_rA`). The ABI passes eight arguments in r0-r7 (§4).
16. **Cells added with the 726-form table** (besides the loops of item 10 and the splits of item 14): `op2z? rA`
    (the 16-bit op 2 with x = 0 and B = 0 is not a shift by 0), `lsl / asr r8-r15, #B` (the h = 1 cells), the W6 cells
    with h = 1 (`ld.h / st.h rB, [r8+rrr]` and `[rA]+` in the first slot), `sub r14, #f12/2` with any F / F'
    (R-spsub), `st.w [sp], #imm14` (R-stimmsp: the ninth stack argument), `st.abs` with the hi F' = 0 (R-stabs0),
    `add rB, rB, #imm27` / `st.h? [rB], #sat` selected by the immediate value (addq: the saturation constants 0x7fff,
    0x8000, 0x7ffe, 0x3fff, 0x1fff, 0xfff are the `in` / `notin` value lists of the entries; also the cell-E
    triples), `add? rB, r15, #rot12` / `ld.h? / ld.hu? rB, [r15±off]` with the F' = 0 tail (R-1eX0F0),
    `saturate? rd, rs1` (op c with B = 0 and rd = rs1), `movi rA, #simm6` in the delay slot of a validated branch
    (R-movi6d), `ld.h / ld.hu` without the `?` for R-ldF0 (S = 0), R-hhttF0, R-F0d and R-1eX0, `ld.hu rd, [rA+rB]`
    (X = 4), the 16-bit `lea` (no `?`), `movi #-32768 / #-32767`, `mtcsr #0x30-0x3e` (`mtcsr_acc`).

17. **The parallel packet, the 22-bit branches, the slot pairs and the guards of the 760-form table.** The packet
    model is settled: the instructions of a packet execute in parallel and every read sees the state before the
    packet (`USIP_PACKET_EXEC_PARALLEL`; the R-waw penalty and the K-tie cascade stay, no rule depends on an
    intra-packet order). **Before the layout**: slotpair0 (a 2-unit packet `[0][0][m][h][rrr][x][B][o3 100]`
    `[1][0][…][o3' 100]`, low 12 bits ≠ 0 in both, whose 32-bit reading has no name — no entry, kind other / fmt, a
    failed guard or an undone pair — is `stslot ‖ stslot` (`stslot_F0` / `stslot_F0_k16`), never ambiguous); the
    prefix forms with the **22-bit displacement** (`disp` = 2·sext22(`U1[7:0] : T[13:12] : T[11:0]`); the U1 low byte
    and the T tt are free in the masks) and the **64-bit X variant** (`bcc48_*_64x`: U0 with F = 0, any extension unit
    with bit 15 = 0 other than `1e0d`; `guard:not_over_validated_call32`: not taken when U0 + X read, as an adjacent
    pair in the first slot, as a `call` / `b` whose target is a function start; the branch keeps the three units
    U0 U1 T, X is decoded on its own as the first 16-bit instruction of the delay slot, the units from 4 on are the
    rest of it). **In the layout**: the guard `loop_b4_straddle16` of the twelve `loop #N` entries (bit 4 of the head,
    field `b4`, must equal `straddle16(last)` = the packet that starts at `last` crosses a 16-byte line:
    `(last / 16) != ((last + 2n − 2) / 16)` with n its units; a contradiction is `.word`, like a failing target guard;
    an unknown packet at `last` accepts); the **`loop #N?` rule** (`USIP_LOOPQ_*`: a `loop#` reading with N = 0 or a
    tail d12 in {0x100, 0x200, 0x400} prints `loop#? #N?, last=…`; the explicit candidate loopcand does not admit it);
    `ctx:tail_at_plus2` (`beqz_F0c` / `bnez_F0c` / `bleu_rr_F0c` / `bltu_rr_F0c`, `bne_imm8_F0s0` / `blt_imm8_F0s0`:
    the single tail EXACTLY at +2, at any other distance the entry falls through to the next one of the cell — the
    DSP pairs of op c —, NOT `.word`; with the tail at +2 and a target that is not a packet start the pair is `.word`);
    `ctx:rf0dall_guards` (`rf0dall_ld_h / ld_hu`, group f0ctx after `rf0d_*`: the tail f12 is even, the unit at +2
    does not decode in tail position as a trusted 16-bit op — mov inc dec rsub add addi mul st.w ld.w mfacc lsl lsr
    asr sub and or xor sext16 zext16 movi st.h ld.h ld.hu st.b ld.bu — nor as control, the head is not `4400` right
    after an op f head with x = 1, the middle unit as a 16-bit op does not write r14; the f0ctx group is tried inside
    the layout, before the post-layout renames: `ld_h_Fp0` never sees those pairs); the score rules lr32 (−1 for a
    reading with a jump / call, or the rest of a `call.abs` / `b.abs` packet, that contains `mov32 r15, #X` with X a
    packet start of the same function), rr7 (+0.25 for a `movi rB, #imm17` formed while an earlier op 7 head of the
    reading with x = 0 stays bare), spodd (+1.0 for a bare 16-bit `addi r14, #imm` with imm not a multiple of 4) and
    the rf0dall nowaw (+1.0 when another instruction of the reading writes the destination of an `rf0dall_*` head).
    **After the layout**: `bz_s_P4_F0` (after `bz_s_P4_u4`, before the R7 gate: `000h rrrd dddd d101` at k = 0 of a
    packet of 2 or 3 units whose head has no named reading and is not the bare `.hword` op 5 x = 0 unit, rA ≠ r14,
    d6 > 0, the target a packet start of the same function beyond the packet: `bz.s rA` + the delay slot — at 2 units
    the second unit as a 16-bit op, at 3 the rest re-parsed); the post rules of the final reading, before the split
    pass and also after the prefix paths: **R-add2** (a packet of ≥ 3 units, a bare `.hword` op 0 F = 0 head at unit
    i — `.hword` only: the bare m = h = 0 units of a non-first slot read `.ext` and never fuse — and a bare unnamed
    closer `[1][1][00][f12 ≡ 0 mod 4]` at unit i + 2 become one `add rB(!x), rA(!m), #rot12` unless another
    instruction of the packet writes rB) and **R-fslot0c** (a bare `.hword` / `.ext` F-slot0 unit
    `[0][0][0][0][rrr][x][B][o3 100]`, low 12 bits > 1, at unit 1 of a packet whose instruction 0 is a call /
    call.abs / callr / call16 is `stslot`); in the split pass **R-slotc** (a pair read with an op c head with F = 0
    and a single tail with tt = 00, rd ∈ {4, c}, a ≠ 8, not the (0, 0) cell with B = 0, low 12 bits > 1 when F' = 1,
    whose reading is `.dsp` / `.word`, `msu?` / `shr.a?` / `mac.9a?` / `mac.92?` or `mac` / `mul.a` / `mul3216.a` /
    `L_mac.a` with rd > 3 → `stslot_slotc_h ‖ stslot_slotc_t`, with the nowaw guardian), the F-slot0 readings by rule
    (R-slot4n / slotpair0 / R-fslot0c with k ≥ 16 → `stslot_F0_k16`; only the F = 0 head of a split `.op4imm` pair
    with k ≥ 16 or in a multi-unit packet keeps `stslot_F0_q`) and `ldslot_S0_pos1` without the `?`; **after the
    packet**: slotc_mark (the slot pairs without a call — kinds call / call16 / calla / callr — in their packet or in
    the two following packets take the `stslot?` twins `stslot_slotc_h_q / _t_q`). The other cells added with the
    table: `movi rB, #imm17` (the op 7 head with the null-field tail `S P00 … 00f1`: a 17-bit rotated immediate
    `USIP_A_ROTIMM` with `nbits = 17`; with m = 0 the value is −65536 / −65535, not −32768 / −32767: `movi_min16` /
    `movi_m32767` are gone), `movhi` with the small F' = 0 tails (`c001` → `0x10000000`, even f12 → `0x1000..0x7000`),
    the 16-bit `ld.w rB, [rA ∓ 4]` of the first slot and the one-unit `st.w rB, [rA ∓ 4]` (R-ld16k0 / R-st16k0),
    `addi rA, #−4 / −2 / −1` of the class-E cell (R-addiE), `loop rX, last, x16` (B = 1: the former `loop.b1?`), the
    m = 1 `loop #N` without the `?`, `saturate`, `mfacc` of the C cell and `sext16 / zext16` with S = 0 without the
    `?`, and the CSR names `ag0-ag3.{base?, len?, idx?}` for 0x30-0x3e.

Operand fields are given as bit ranges over the big-endian concatenation of the instruction's units (bit `width-1`
= bit 15 of the head): 32-bit forms = head bits 31..16, tail 15..0; 48-bit = head 47..32, hi 31..16, lo 15..0; 64-bit =
head 63..48, ext 47..32, U1 31..16, T 15..0. When the units are not adjacent in memory the plugin gathers them (head,
then its tails in round-robin order) before applying mask/value.

## 2. The table

`tools/gen_usip_tables.py` emits every field referenced by the format string or by a constraint (`nfields` >=
`nargs`), the constraints as structured `UsipCons` records (op, field indices, values), the `rename_from` lists of the
rename entries, the indices of the context-only forms (`USIP_FORM_*`, incl. `hi1010_loose`, the split and the fusion
entries) and the auxiliary tables
of the ISA description (`usip_must_pair`, `usip_sys_fld4[16]`, `usip_cond_bcc48[5][4]`, `usip_csr_ext[64]`,
`usip_kind_names[]`, `usip_save_set[8]`, `usip_never_tail[]`, `usip_never_head_with_tail[]`, `usip_c48_table[]`,
`usip_br0_cells[]` / `usip_br0_cells_weak[]` (`UsipBr0Cell`: op, tt, class, distance), the sorted `usip_c48sym_table[]`,
`usip_value_sets[]`); the generated header is `usip_opcodes.h` and regenerating it is byte-identical. Form names are
sanitised into C identifiers for the `USIP_FORM_*` indices. Limits: `USIP_MAXRANGES 8` (the movhi V20
field collects 8 ranges), `USIP_MAXFIELDS 12`, `USIP_MAXCONS 8`, `USIP_MAXVALS 12` (the `fup` cell set); the 16-bit
forms may only use `packet_len` 1/2, `packet_len_ge` 2, `head_index` 0 and `head_pos_ge` 2 (the 16-bit match cache is
keyed by those classes), except the rename and the context-only entries, which are evaluated with the exact head
index after the layout. The constraint ops `tail_adjacent` (`USIP_C_TAIL_ADJACENT`, `vals[0]` = 0/1; also the `any`
sub-operation `USIP_ANY_TAIL_ADJACENT` with field `USIP_NOFIELD`), `ieee_short` (`USIP_C_IEEE_SHORT`, `vals[0]` =
significant digits), the membership in the 48-bit value table (`USIP_C_IN_C48TAB`, emitted for an `in` set equal to
the table), `br0_cells` / `br0_cells_live` (`USIP_C_BR0_CELLS` / `USIP_C_BR0_CELLS_LIVE`: field = rB, `vals[0]` = a
cell mask, `USIP_BR0_BIT(class, dist)`), `bf_valid` (`USIP_C_BF_VALID`, fields w / pos), the guards `tail_named16`
(`USIP_C_GUARD_TAIL_NAMED16`) and `target_packet_start_any_or_function_start` (`USIP_C_GUARD_TARGET_PK_ANY_OR_FN`),
the value sets too large for `vals` (`USIP_C_IN_SET` / `USIP_C_NOTIN_SET` into `usip_value_sets[]`), the `any`
sub-operations `USIP_ANY_PACKET_LEN`, `USIP_ANY_GUARD` (`enum usip_guard_id`), `USIP_ANY_RANGE` (`lo | hi << 16`) and
`USIP_ANY_BR0_CELLS` / `USIP_ANY_BR0_CELLS_LIVE`, `USIP_ANY_INSTR_INDEX` and `USIP_ANY_CTX` (an `any` holds up to four
alternatives, `USIP_MAXANY 4`, which may be a context condition or an instruction position), the instruction position
`instr_index` (`USIP_C_INSTR_INDEX`, on the rename entries), and the context conditions `USIP_CTX_COP_RA_IN_PACKET` /
`USIP_CTX_NOT_C48_LO_FOLLOWS` / `USIP_CTX_B111_LAYOUT` … `USIP_CTX_REST_NAMED_NO_Q` / `USIP_CTX_NOT_LOOP_REG_HEAD` …
`USIP_CTX_SPLIT_UNIT`, are evaluated by the decoder with the packet context (`USIP_CTX_TARGET_BEYOND_PACKET`,
`USIP_CTX_DELAY_SLOT_NOT_WRITING_RA`, `USIP_CTX_OP4IMM_HEAD_MULTIUNIT`, `USIP_CTX_SPLIT_UNIT` and
`USIP_CTX_DELAY_SLOT_OF_VALIDATED_BRANCH` by the explicit procedures of items 14 and 15 — the `bz.s` rules, the split
pass, `decode_asg` — and accepted by the generic constraint check). `USIP_F_SPLIT` marks the entries of the split
procedure (`split_role` in the JSON: `either` = the head or the re-read tail of a split pair, `bare` = a bare unit
renamed before the pass, also `USIP_F_SPLITBARE`), `USIP_F_FUSE` the fusion entry; every one of them has a `USIP_FORM_*`
index.

With the 760-form table the header also carries the guards `loop_b4_straddle16` (`USIP_C_GUARD_LOOP_B4_STRADDLE16`,
exported with the head field `b4`) and `not_over_validated_call32` (`USIP_C_GUARD_NOT_OVER_VALIDATED_CALL32`), the
context conditions `USIP_CTX_TAIL_AT_PLUS2`, `USIP_CTX_HEAD_UNNAMED_NOT_LSL0`, `USIP_CTX_RF0DALL_GUARDS`,
`USIP_CTX_SLOTC_PAIR`, `USIP_CTX_CALL_WITHIN_2_PACKETS`, `USIP_CTX_OP4IMM_HEAD` and `USIP_CTX_ADD2_FREE_CLOSER`
(evaluated by the explicit procedures of item 17: the f0ctx pass, the post rules, the split pass and `slotc_mark`),
`USIP_F_FUSE | USIP_F_ADJ2` for the fusion at distance 2 (`add2_rot12`), the constants of the packet model
(`USIP_PACKET_EXEC_PARALLEL`) and of the `loop #N?` rule (`USIP_LOOPQ_ENABLED`, `USIP_LOOPQ_N_EQ`, `usip_loopq_d12[]`);
`USIP_A_ROTIMM` with `nbits = 17` and the three-range `USIP_A_DISP` of the 22-bit displacement need no generator
change, `usip_csr_ext[]` carries `ag0-ag3.{base?, len?, idx?}`, and the `rename_from` symbols `@slotpair0` /
`@fslot0c` / `@slotc_tail` / `@free_closer` are plain strings (the split and fusion entries are applied by index, never
by the generic rename pass).

`usip_opcodes[]` is ordered: the first entry of the right width whose `(units & mask) == value`, whose `flags`
allow the slot, and whose `cons` holds is the reading (entries with `USIP_F_RENAME` are excluded from that matching:
item 1.11). Fields of each entry: `name` (mnemonic), `form` (stable id = `usip_isa.json` `forms[].name`),
`value/mask`, `width/nunits` (16/32/48/64), `flags` (`USIP_F_SLOT0`, `NOTSLOT0`, `CTX`, `DELAY`, `ADJ1`, `ADJCTRL`,
`NAMED`, `NOTAIL`, `ADJ2`, `UNKNOWN16`, `ADJDEF`, `PREFIX`, `RENAME`, `HHTT`, `GUARDFT`, `B111`, `F0CTX`, `FUSE`,
`SPLIT`, `SPLITBARE`; a `ut32`),
`kind`, `conf`, `fmt` + `fields[]`
(operand template and bit fields, up to 8 ranges), `cons[]`, `rename_from` / `nrename_from` (the readings a rename
entry may replace).

Operand value transforms (`UsipField.type`): `reg` (`rN`; the `{N:!}` template token prints the high-bank `!`;
`base` holds a constant ADDED to the field — `rB1 = rB + 1` of `ld.d/st.d`, `sh = m + 1` of the 16-bit `lsl`, `12 + 8x`
of cell A), `imm` (× `scale` when declared: `addsp`, `lea?`, `ld.d? b10` ×4, `ldslot` k), `simm` (sign-extend to the
total field width, × `scale`: `ld.d/st.d` offset = 4·sext10(s:v9), the bcc48 imm9), `rotimm` (`rot(f,n)`: bit 0 is the
sign), `urot`, `disp` (signed, × `scale`, pc-relative: target = head address + value; for the prefix forms the head is
the packet start), `udisp` (loop end, inclusive), `absaddr` (`base | value`, `base = SEG[A] = A << 26`, `0x78000000` for
the hi(1010) family `lea/lea?`), `acc`, `accw`, `csr` (unused), `csr_ext`, `flag`, `movhi` (the collected bits — V20 =
`i:t1:t0:f12[0]:m:h:rrr:f12[11:1]` for `movhi`/`movhi_tt10_short`, `f12[11:1]` for `movhi_small` — `<< 12`), `offh`
(half-word offset: `f` even → `f`, odd → `f − 0x1001`), `offw` (W14, a 14-bit word displacement: `(f & 3) == 2` →
`0x1000 + (f & ~3)`; `(f & 3) == 3 && f >= 0x800` → `4·sext10(f >> 2)`; else `f`), `offb` (the byte displacement of
`ld.b/ld.bu/st.b`: `sext12(f[0] : f[10:1] : f[11])`, bit 11 of the field is bit 0 of the displacement and bit 0 the
sign; printed with its sign), `loopn` (the collected bits as is: head bits 13:5). An immediate glued to a letter or
to `=` (the accumulator index `A{k}`, the loop `?ss=N`, `save w=N`) is printed in decimal. The 48-bit constants use a
plain 32-bit `imm` field `val` =
`head[13:9] << 27 | hi[12:0] << 14 | lo[13:0]`. The bit-field position `pos` of `fxtu/fxts/fup` is a plain `imm`
whose ranges `[0,0],[4,1]` implement `rotr5(p)`.

Bank bits: `x` (head/unit bit 8) is the bank of **rB** (destination / data), `m` (bit 13) is the bank of **rA**
(source / base; also the compared register of the 32-bit `b<cond>` and the destination of the 16-bit `movi rA!,
#imm5`), and for op 7 `ss & 2` (head bit 13, field `ss1`) puts **rs1** in the high bank (also in `bset/bext rd, rs1,
rB` and the bit-field family). Templates print them as `{x:!}`, `{m:!}`, `{ss1:!}`.

Constraints that are not mask/value (`cons` records, evaluated by `cons_ok()`): address windows (`call.abs`, `mov32`
windows), `B != 0` for `sys`, `rA not in {14,15}` for the 16-bit `bz.s/bnz.s`, the near-`b` displacement range, the tail
guards (`setcc_tail`, `tail_not_named16`, `or2_tail`), `field >= n` / `> n`, `field in [..]` on hidden fields (`u9`,
`rA5`, `f12`, `csr`, `lo4`, `mh`, `op`, `A`, `hi12`, `u16` and `f12` of the bit-field cells; large sets as 64-bit
membership masks), `val` in the 48-bit value table, `even` / `odd`, `any` (up to three alternatives incl. set
membership and `tail_adjacent`), `packet_len == n` (stand-alone units; `== 3` for `add32_0eX0_L1`), `packet_len >= n`,
`head_index == n` / `head_pos_ge n`, `ctx:not_ext_of_op67`, `ctx:cop_rA_in_packet`, `ctx:not_c48_lo_follows`,
`tail_adjacent == true/false`, `ieee_short(imm, 3)`, the target guards and `guard:head_not_validated_bs`,
`br0_cells [[class, dist], …]` (the (B class, tail distance) cells of an F = 0 branch head: B0 = B == 0, B15 = B == 15,
B = other; distance 1 / 2; `br0_cells_live` for the five weak cells, which never hold in the plugin), `bf_valid(w,
pos)` (1 ≤ w and w + pos ≤ 32), the guards `tail_named16` (`hhtt_st_w_t5_F1S0`: the W14 text only with a named 16-bit
tail) and `target_packet_start_any_or_function_start` (`b_near`), the context conditions `b111_layout`,
`hhtt_second_head`, `f0d_triple`, `bfpair`, `bf_dst_not_written`, `between_dsp_head_and_tail` (unused),
`rest_named_no_q`, `any` with the sub-operations `packet_len == 2` / `guard:…` (`bz_s_P5`: evaluated by its context
rule), `guard:tail_not_named16` / `csr in [0x30, 0x3f)` (`mtcsr_q`, R-mtacc) and `br0_cells` / `br0_cells_live`, the
large value sets of the BF_SEL cells (`USIP_C_IN_SET` / `NOTIN_SET`), and the 16-bit entries whose **mask includes
bit 15 = 1** (closers). The context-free constraints are evaluated by the pairing
predicates; the position / length / context / adjacency constraints are deferred to the decode of an assignment (a
failure falls through to the next entry of the cell), followed by the b.s guard (undo) and the target guards (`.word`).
`kind` values: see `enum usip_kind`.

Context rules (not table entries, see `usip_isa.json structure.context_rules`): `hi_lo_fam_before` (`.hi/.lo`),
`.ext` (`fX?7` after a `ld/st` whose tail has S = 0), `.be79`, `bz_s_P4`, `slot_S0_R7` / `lea_sp_S0`,
`op8_slot_split`, `sgt_closer_pair` (`4NN7 cc00`), `cells_by_position`, `not_ext_of_op67`, `nop_ctl`, `cop_addi32`,
`renames_post_layout`, `bz_s_P5`, `f0d_middle_unit`. `structure.sys_ops` lists the `sys`-shape families by tail field
(fld 0 `ret`/`jr rB`, 1 `call rB`, 2 `ret?`, 4 `cop/rti/lpexit?/isync?/ieon/ieoff/sys? #13/idle`) and the F = S = 0 twin;
`structure.conditions.bcc48` the 48-bit condition table and `S0F1_tail_variants` the `[0][1][tt]` branch tails;
`structure.registers.io_ports` the port map of `ior/iow`; `structure.packet.kties` the K-tie cascade.

What the table cannot express (rules of the decoder, documented in `structure.packet`): the group / round-robin
enumeration and its bare-head filter, the explicit candidates (3-unit F' = 0, H H T T, `0e10 3fc0 c000`), the layout
order `(s0, I, Fv, −A, K)` and the tie-break penalties (incl. P2W and callin), the late evaluation of the guards, R0/R7,
the never-tail / never-head-with-tail rule, the op8 slot split, the partial admission of the 48-bit value table, the
fall-through guards (R-tgt), the `b111` and `f0ctx` groups, the re-read of the R-F0d middle unit, the `bz_s_P5` rule,
the post-layout renames, the K-tie cascade.

## 3. Confidence and what is format-only

* `high`: encoding and operation established by independent checks — the whole control flow (`b<cond>` incl. the
  48/64-bit `b<cond>.l` and the `b<cond>.d` S0F1 cells, `call`, 16-bit branches, `loop` incl. `loop #N`, `call.abs`,
  the F' = 0 tails), ld/st with offset incl. the signed `ld.d/st.d`, the negative half-word offsets and the 14-bit
  word offsets (W14), the 16-bit ALU, the 32-bit ALU, `movi21`, `mov32/add` by formula and by the value table,
  `movhi`, the basop/DSP family, mul/div, bit ops incl. `fxtu/fxts/fup` and the register `bset/bext`, CSR access,
  port I/O, `save/restore`, `nop32`, `cmov r15`, `sne`, `seq`, `slt`, `sgt`, `addsp`, `osl`.

## 4. ABI (for `regs()`)

`r14 = SP`, `r15 = LR`, arguments `r0-r7` (r0-r3 most used, stack args > r7 at `ldslot #k` = SP + 4k), return `r0`
(`r0:r1` for 64 bits; 64-bit products live in the accumulators `A0-A3`), callee-saved `r8-r10, r12, r13` (+ the
high-bank copies) via `save w` (`w = 2` saves `{r11!,r12!,r13!,r14!}`: four words; `w = 4` saves `{LR, r8}`: two
words), `r11` caller-saved. There is **no classic CSR bank** reachable through op 4: that shape is port I/O
(`ior rB, [rA]` / `iow rB, [rA]`). Extended CSRs `0x01-0x3e` via `mfcsr` and `mtcsr #nn, rA`. There are no flags: all
branches are compare-and-branch (incl. the 48-bit `b<cond>.l rB, #imm9 / rA`).

## 5. Known limitations of the table-driven reading

1. **Ties.** Readings tied on `(s0, I, Fv, −A)` go through the K-tie cascade (§1.12, §7); what it cannot decide is
   left to the assignment key `K` and flagged `opex.packet.ambiguous` (a small fraction of the packets, mostly `S S O O`
   and longer packets where several head/tail assignments have the same cost). The `du2` step sees a shorter context
   than a scan of the whole function would give (§7), so a few of its decisions can differ from those of a decoder
   that has the function in hand.
2. **Control flow in open packets** (`call`/`b`/`loop`/`loop #N`/`b.s` followed by delay-slot ops): when the branch
   reading is not the cheapest one the packet reads as `add`/`st.w`/`st.h`/`movi` (a `loop #N` reading with a 16-bit
   middle unit often writes a register twice with the stolen tail, which R-waw charges). A disassembler that knows the
   function table can prefer the reading whose target is a function start or a packet boundary, and can answer the
   `callin` tie-break (a relative `call` into the middle of a function, §6).
3. **Target guards that cannot be evaluated** (§6): far `b` to another function or beyond the lookahead (and the
   readings of the packet behind it), the open-packet `call.s`, and `loop`/`bnez.d`/register `b<cond>`, the
   `b<cond>.d` S0F1 and register cells and the `bz.s` of packets longer than two units with a forward target beyond
   the lookahead are read as data or as the plain 16-bit units.
4. **Rules that need a validated target** (§6): the loop entries not accepted unverified (the m = 1 `loop #N` heads,
   the h = 1 heads except with the S = 1 tail or the adjacent F = 0 tail, the F = 1 head with the S = 0 tail at +2),
   the 22-bit cells and the 64-bit X variant of `b<cond>.l`, the 2-, 3- and 4-unit `bz.s`, R-brHHTT, R-movi6d and
   the R-w6h1 loop guard have no unverified fallback: beyond the lookahead the plain 16-bit readings, the `.hword`,
   the grammar's reading, the `.movi6?` closer and the W6 cell stand.
5. **Windows the plugin cannot always see** (§6): `slotc_mark` needs the two packets after a slot pair (inside the
   lookahead they are first-pass readings, beyond it the window ends and the pair prints `stslot?`), the straddle
   guard of `loop #N` needs the packet at the loop end (beyond the lookahead and the session's cache it is not
   evaluated, and an eight-unit run without a closer counts as unknown), and `not_over_validated_call32` needs
   function starts (without the `function_start` callback a target the session validated as a packet start stands
   in, so a cross-function `call` of U0 + X the session has not seen does not block the 64-bit variant). The plugin
   produces no ESIL for the uSIP mode: the parallel packet would require reading every operand of the packet before
   any write.

## 6. Target guards: what the plugin knows

The decoder asks the caller through `UsipGuardCtx` (`packet_start`, `packet_start_any`, `function_start`,
`inside_function`: yes / no / unknown). `arch_md32.c` answers **packet starts from the stream**: the packet starts
decoded earlier in the session (a hash set in the session state: backward targets, and forward targets of a region
decoded before, e.g. after `aa` or on a second listing) and a scan of the bytes radare2 passes with the op past the
current packet (forward targets; radare2 caps the op bytes at 64, `r_anal_op_set_bytes`), so a forward target farther
than 64 bytes is unknown on a first linear pass. "Same function" is approximated by "reachable in the linear decode"
(no function bounds): a backward target below the lowest packet start decoded in the session (`lo_seen`) is unknown
(another function, or code never listed), one at or above it that was not seen as a packet start is not one. A
definite "not a packet start" rejects the reading even for the guards that also admit a function start: a target the
caller could look at that is not a packet start cannot be a function start either. `packet_start_any` is not
installed (the session's packet starts stand in).
**Function starts are unknown**: an arch plugin has no typed access to RAnal (`RArch.user` is an untyped pointer), so
neither `function_start` nor `inside_function` (the `callin` tie-break: a relative `call` whose target lies strictly
inside a known function pays the out-of-boundary penalty) is installed; both are the hooks for an embedder that has a
function table.

When a guard cannot be evaluated the decoder applies a fallback chosen by measurement on the sample the table was
built from (`unverified_ok()` in `usip_decode.c`, by form name, tail distance, head/tail bits and the direction of
the target): the forms whose
unverified readings are right in nearly every case where they compete are read anyway — `call_F0` (function start
unknown; with the tie-break bonus), `b_F0`, `beqz_d` and the immediate `b<cond>` forms with the F' = 0 tail
(`beq/bne/ble/blt/bgtu/bge/bgt_imm8_F0`, forward target beyond the lookahead), the `bcc48_*` / `bcc48_*_64` prefix
forms in their regular cell (U1 low byte 0 and tt = 00: a forward displacement below 4096 units, beyond the
lookahead), `loop_imm_F1S1`, `loop_imm_F0S0` and `loop_imm_h1_F0S0` with the tail adjacent, `loop_imm_F1_Fp0` (the
F' = 0 tail at +2), `loop_imm_h1_F1S1`, `loop_F0` when the head has F = 1 and the S = 1 tail sits at +2, the op c
F = 1 branches and the op 9 F = S = 0 cells with the F' = 0 tail at +2 (`beqz/bnez_F0c`, `bleu/bltu_rr_F0c`,
`bne/blt_imm8_F0s0`), and the S0F1 cells
`bne/blt/bgeu/bgtu/bge_imm8_s0f1`, `beqz/bnez_s0f1` and `bleu_rr_s0f1`, and the forms whose guard is a validation
filter (`b_s_open`, `b_near`, `loop` / `loop_ssq` / `loop_b1` / `loop_b1_ssq` (the x16 loops) with the F' = 1 tail, the F = S = 0
`b<cond>.d` cells, `bne_d_m1` and the R-br0 `*_f0s0` cells: they were read without a guard before the filter existed,
so an unknown target keeps the reading, the conditional ones only forward); the others are treated as a failed guard —
`call_s_S0` (only a small fraction of the shapes are calls), `b_far` (about a fifth of the unverified readings would
be wrong), `bnez_d` of the F = S = 0 cell (shared with the op C DSP pairs), `ble_rr_F0`/`blt_rr_F0` (shared with
`.ctl15`), the other `loop_F0` tails (`movi || mov` pairs), `loop_imm_F1S0` (the S = 0 tail at +2: wrong too often
when unverified), `loop_imm_F0S0` and `loop_imm_h1_F0S0` with the tail at +2, `loop_imm_h1_F1S0`,
`loop_imm_h1_F1_Fp0` and the m = 1 `loop_imm_m1_*` entries (the 16-bit readings stand), the 22-bit cells of
`b<cond>.l` (backward, or +4096..+8191) and the `bcc48_*_64x` variant with a free extension unit, the S0F1 cells
`beq/ble/bgt_imm8_s0f1`, the op 8 S0F1 cells and the op d S0F1 register cells. The rules that need a validated
target (the 2-, 3- and 4-unit `bz.s`, R-brHHTT, R-movi6d, the R-w6h1 loop guard) have no unverified reading;
slotpair0, R-slotc, R-fslot0c, R-add2 and rf0dall carry no target guard. Backward targets inside the decoded
region are decided by the session (seen = packet start, unseen = not a packet start); below it they are unknown:
unverified for `call`, `b` and `b.s`, never for a conditional branch (a conditional branch does not leave its
function). An accepted-unverified reading prints a trailing `?` (`call?`, `beqz.d?`, `blt?`, `bne.l?`, `loop#?`,
`bne.d?`, `b.s?`, `loop?`; the `loop #N?` rule keeps its own `?` after the count, so an unverified one prints
`loop#?? #N?`), reports `confidence = medium` and `target_guard = "unverified"` in `opex`; a validated
one reports `"validated"`. A 32-bit pair whose target guard failed is `.word`, except the op C compare-and-branch
cell (`bnez.d` with F = S = 0), whose failed pair keeps the DSP shape and is printed `.dsp 0x…` (unnamed data either
way), and the `USIP_F_GUARDFT` entries, whose failed guard falls through to the next entry of the cell (two 16-bit
ops when none is left).

Two guards of the 760-form table are not target guards. The straddle guard of `loop #N` (`loop_b4_straddle16`: bit 4
of the head must agree with "the packet at the loop end crosses a 16-byte line") is answered through
`UsipGuardCtx.packet_units`, which `arch_md32.c` serves from the bytes at hand or from a packet decoded earlier in the
session; a contradiction is `.word` like a failed target guard, an unknown packet accepts. `not_over_validated_call32`
(the 64-bit `b<cond>.l` with a free extension unit is not taken when U0 + X read as a `call` / `b` whose target is a
function start) is exact with the `function_start` callback; without it a target the session validated as a packet
start stands in.

## 7. The K-tie cascade in the plugin

`usip_decode_packet` runs the cascade of §1.12 on every packet whose readings tied on `(s0, I, Fv, −A)` (`cascade()`
in `usip_decode.c`: `decide_ties`, `regs_of`, `du2_scores`):

* **`dedup`** and **`nowaw`** only need the tied readings of the packet itself: the instruction texts (without the
  unverified `?`) and the registers each instruction writes and reads are derived from the text (`rN`/`rN!`/`sp`/`LR`
  tokens, the base of `[rA]+` as a destination, the first operand as the destination when it is a register or a pair,
  the read-modify-write forms, stores and system ops reading everything).
* **`du2`** needs the neighbouring packets. The decoder asks the caller for them through `UsipGuardCtx.packet_at`
  (the packet that ends at an address: the backward context; the packet that starts at an address: the forward
  context) and `branch_target` (the join points). `arch_md32.c` supplies the packets decoded earlier in the session
  (their final readings, from the packet cache) and the **first-pass readings** of the packets that follow inside the
  bytes at hand (decoded with `USIP_GUARD_NO_CASCADE`, so a context packet never runs its own cascade), plus the
  targets of every branch decoded so far. Approximations versus a scan of the whole function with first-pass
  readings: the forward window ends at the 64 bytes radare2 passes (the cascade would look eight packets ahead), the
  backward packets are already-cascaded readings, the join points only include the branches seen so far, and an
  exhausted window is "no event" where a scan that knows the function start would report an argument / undefined
  register. `dedup` and `nowaw` do not depend on the context; a few `du2` decisions do, and a tie `du2` cannot decide
  with the shorter context is left to K (flagged ambiguous).
* `opex.packet.tiebreak` reports `dedup` / `nowaw` / `du2` for a packet decided by the cascade;
  `opex.packet.ambiguous` is true only for the ties the cascade could not decide (K decides them).
* A packet read by the `bz_s_P5`, `bz_s_P4_u4`, `bz_s_P4_F0` or `bz_s_P4_u3` rule parses the rest of the packet as an independent
  packet (its delay slot): the ties of that parse are the ones the cascade sees, and the rule is applied again to the
  reading the cascade chooses.
* The packet-level rules run on the chosen reading in a fixed order — `bz_s_P4`, `bz_s_P4_u4`, `bz_s_P4_F0`, R7 /
  `lea_sp_S0`, `bz_s_P4_u3`, S3, `.be79`, the post rules R-add2 / R-fslot0c, the split pass (items 14 and 17) — then
  the generic renames, the fusion and `slotc_mark`; the cascade compares the renamed and fused texts, and after its
  decision the same passes run again on the reading it chose.
