# uSIP (MD32 family, VLIW packet variant) — ISA table notes for the `usip` CPU mode

Reference for the table format, the constraint semantics and the packet model behind the `usip` CPU mode.  Everything
in it is implemented by `usip_decode.c` (packet model), `tools/gen_usip_tables.py` (table) and `arch_md32.c` (RAnalOp
mapping); see README.md "uSIP mode" for the user-facing description.  Files:

| file | what |
|---|---|
| `isa/usip_isa.json` | the machine-readable table: `meta`, `structure` (packet model incl. the layout order, the prefix and grammar rules, registers, CSRs, system ops, I/O ports, conditions incl. the 48-bit condition table, displacement and immediate formulas, field types, context rules) and the ORDERED list `forms` |
| `usip_opcodes.h` | the same forms as a C table (`UsipOpcode usip_opcodes[]`), generated by `tools/gen_usip_tables.py` |
| `usip_decode.c` | the packet decoder (`parse_group`, `group_parses`, `decode_asg`, `score`, `fviol`, `parse_packet`) |

## 1. The packet model

The earlier `usip_decode()` read one 16-bit halfword and, when bit 15 was 0, paired it with the next halfword. That is
wrong in general: **the unit is the 16-bit halfword and the instruction stream is a VLIW packet stream.**

1. **Unit scan.** Read halfwords (big-endian) from the packet start. A packet = consecutive units up to and
   including the first unit with **bit 15 = 1** (max 8 units). Packets start at `addr % 4 == 2` as often as at
   `addr % 4 == 0`: never assume 32-bit words. Branch targets are packet starts.
2. **Heads and tails.** Inside a packet, a unit with bit 15 = 0 is either a *head* (first unit of an instruction) or
   a *tail* (second/third unit of a 32/48-bit instruction). Instructions are **head + 0, 1 or 2 tails**, 16/32/48 bits
   (64 bits only for the `bcc64` prefix forms: head + `1e0d` + U1 + T). A head without a tail is a 16-bit op "with the
   packet still open" (its bit 15 is 0 but it is decoded like the bit-15 = 1 form; most 16-bit entries of the table mask
   bit 15 out, the stand-alone *closer* forms keep it).
3. **Prefix forms.** Before anything else, if the packet opens with the three (four) units of a `bcc48` (`bcc64`) entry
   (`USIP_F_PREFIX`: U0 op b-f with F = 1 (F = 0 + `1e0d` for the 64-bit twin), U1 `[0][1][m'h'][rrr'x'][00000000]`, T
   `[S][1][00][d12]`) AND the target `packet start + 2·sext12(d12)` is a packet start of the same function (≠ the packet
   itself), those units are ONE instruction and the rest of the packet is its delay slot (parsed as an independent packet
   without control flow). A failing guard means the entry is simply not taken (normal layout, never `.word`). The absolute
   `call.abs/b.abs` prefix (`x008 + hi + lo`, rule R) is unchanged.
4. **Layout (head/tail pairing).** Tails are not necessarily adjacent to their head: the packet is *heads first,
   then tails*, and the tails are dealt **round-robin** among the heads that take tails, in head order (`S S O O` =
   two 32-bit instructions interleaved). A packet may also be a sequence of *groups*, each laid out that way
   (one-instruction groups = contiguous layout: `b dest ‖ delay-slot ops`). No bit selects the layout. The decoder
   enumerates every group split and every head/tail assignment allowed by the table (a head may take a tail iff some
   non-context form matches head+tail; a head may stand alone unless it is in `structure.packet.must_pair`;
   `ret/save/restore` never take tails; **`5e0d` is never a tail**), discards, inside a group, the assignments with more
   bare heads that have no named 16-bit reading, adds the explicit candidates (`[head][op16][F' = 0 tail]` for 3 units,
   **H H T T** = `[h0][h1][t0 S=0][t1 S=1]` with two named ld/st for 4 units) and ranks the readings with the
   **prior-free total order** (`structure.packet.layout_order`): `(s0, I, Fv, −A, K)` ascending, where `s0` = unknown
   units (kind `other`: 1 per unit; kind `fmt`: 1 per instruction) + the tie-break penalties of
   `structure.packet.tie_breaks` (R7 credit, O syllables, loose `4000`, alignment except `f12 ≡ 3 ≥ 0xf00`, the add
   relabel, 1dX6, `.hi/.hilo`, the fam48 r14/r15 destination, the store-of-immediate triples, the identical-units rule
   of 4-unit packets, the mfcsr pair, the validated-guard −0.5), `I` = number of instructions, `Fv` = heads with a tail
   whose adjacency contradicts the **F pattern** (head F = 0 and next unit bit 14 = 1 ⇒ adjacent tail, otherwise
   deferred), `−A` = minus the number of adjacent tails, `K` = the sorted tuple of `(head index, (tail indices…))`
   (smallest first). Readings tied on `(s0, I, Fv, −A)` and decided by `K` are the **ambiguous** packets unless the tied
   readings are identical. No learned prior and no group count take part. Rule **R0**: the final closer (bit 15 = 1)
   may be a one-unit group of its own even when it has no named 16-bit reading. Rule **R7**: a bare first-slot unit with
   bit 15 = 0 of the slot family (or of the `lea?` shape with rA ≠ r14 when no other instruction of the packet has a
   tail) counts as a named unit when every other instruction of the packet is named, and is printed through the context
   forms `ldslot_S0`/`stslot_S0`/`lea_sp_S0`. When no group parse exists a greedy fallback pairs each head with the next
   free unit if some form matches.
5. **Slot 0.** Only the first unit of a packet can be control flow (branches, `call/b`, `loop`, `loop #N`,
   `bcc48/bcc64`, 16-bit branches incl. `call.s` with bit 15 = 0, `beqz.d/bnez.d` with F = S = 0, `call.abs/b.abs`);
   forms flagged `USIP_F_SLOT0` must not be matched elsewhere. The 32-bit `ret` (`40ff c000`), `ret?`, `jr rB`, `call rB`
   and the `sys` twins with F = S = 0 are NOT slot-0 forms. Tail adjacency of the control forms (`USIP_F_ADJCTRL`: +1
   with S = 1 or +2 with S = 0; `USIP_F_ADJ2`: exactly +2 for the F' = 0 control tails AND for `loop #N` with F = 1,
   S = 0 — at +1 that one is two 16-bit ops, not `.word`; `loop_F0` also at +2 with S = 1). **Target guards**
   (`cons = "guard:target_*"`): for 32-bit forms evaluated AFTER the mask match, a failure makes the pair `.word` (no
   fall-through); for the 16-bit `call_s_S0` a failure falls through; for the prefix forms a failure means "not taken".
6. **Deferred tails and undo.** `USIP_F_ADJDEF` (`st.h` with the F' = 0 tail, R-st1h): the tail must be at +2 or
   farther; an adjacent tail undoes the pair into two 16-bit ops. `guard:head_not_validated_bs`: in the first slot,
   when the head is a 16-bit `b.s` shape (`5cX1/7cX1`, not m = 0 with d6 = 0) whose target is a packet start of the same
   function, the pair is undone (the `b.s` wins). `USIP_F_ADJ1` (immediate set-on-compare, `add_FS12`, `seq/slt` of
   op 6): a farther tail undoes the pair.
7. **Position selectors.** Constraints `head_index == n` / `head_pos_ge n` (unit index of the head inside the packet)
   and `packet_len >= n` select the identical-bit cells by position: `ld_w16_A_k0` (k = 0, `USIP_F_RENAME`: scored as
   its underlying `.sub?` reading), `mfacc_q_C_k2` (k ≥ 2), `cellE_st_h_q_k1` / `cellE_add_q_k2`. Entries whose
   deferred constraints fail FALL THROUGH to the next entry of the same cell. `ctx:not_ext_of_op67`
   (`add_FS1_rot12_odd`) needs the first unit of the packet.
8. **Context forms (`USIP_F_CTX`).** `bz_s_P4`, `ldslot_S0/stslot_S0/lea_sp_S0` (R7), `ldslot_split/stslot_split` (the
   two halves of an `.op8?`/`.op8.t?` pair of slot-family units, context rule `op8_slot_split`) and the `hhtt_*` ld/st
   forms with F ≠ S (only inside the H H T T candidate; the `not_hi1010` constraint is ignored for the first head, and
   for the second when the first is not a 48-bit-family head).
9. **Delay slot = the rest of the packet.** When the control instruction does not close the packet (`call`/`b` with
   an S = 0 tail, `b<cond>.d`, `b<cond>.l` with S = 0 on T, `ret.d`, `b.s` with bit 15 = 0, `call rB`, `call.abs`),
   every other unit of the packet executes before the transfer (on both paths). For radare2 this means `op->delay` =
   number of remaining instructions in the packet, and the branch instruction's `size` covers only its own units while
   the fall-through address of the packet is the next packet.
10. **Hardware loops.** `loop rX, last=pc+disp12` and `loop #N, last=pc+disp12` (`USIP_A_LOOPN`: N = `((rrr:x:B) >> 1)
    + [x:B ≠ 0]`): `last` is the address of the LAST instruction of the body (inclusive); the body is the following
    1-16 instructions.

Operand fields are given as bit ranges over the big-endian concatenation of the instruction's units (bit `width-1`
= bit 15 of the head): 32-bit forms = head bits 31..16, tail 15..0; 48-bit = head 47..32, hi 31..16, lo 15..0; 64-bit =
head 63..48, ext 47..32, U1 31..16, T 15..0. When the units are not adjacent in memory the plugin gathers them (head,
then its tails in round-robin order) before applying mask/value.

## 2. The table

`tools/gen_usip_tables.py` emits every field referenced by the format string or by a constraint (`nfields` >=
`nargs`), the constraints as structured `UsipCons` records (op, field indices, values), the indices of the
context-only forms (`USIP_FORM_*`) and the auxiliary tables of the ISA description (`usip_must_pair`,
`usip_sys_fld4[16]`, `usip_cond_bcc48[5][4]`, `usip_csr_ext[64]`, `usip_kind_names[]`, `usip_save_set[8]`); the
generated header is `usip_opcodes.h` and regenerating it is byte-identical. Limits: `USIP_MAXRANGES 8` (the movhi V20
field collects 8 ranges), `USIP_MAXFIELDS 12`, `USIP_MAXCONS 8`, `USIP_MAXVALS 9`; the 16-bit forms may only use
`packet_len` 1/2, `packet_len_ge` 2, `head_index` 0 and `head_pos_ge` 2 (the 16-bit match cache is keyed by those
classes).

`usip_opcodes[]` is ordered: the first entry of the right width whose `(units & mask) == value`, whose `flags`
allow the slot, and whose `cons` holds is the reading. Fields of each entry: `name` (mnemonic), `form` (stable id =
`usip_isa.json` `forms[].name`), `value/mask`, `width/nunits` (16/32/48/64), `flags` (`USIP_F_SLOT0`, `NOTSLOT0`,
`CTX`, `DELAY`, `ADJ1`, `ADJCTRL`, `NAMED`, `NOTAIL`, `ADJ2`, `UNKNOWN16`, `ADJDEF`, `PREFIX`, `RENAME`, `HHTT`),
`kind`, `conf`, `fmt` + `fields[]` (operand template and bit fields, up to 8 ranges), `cons[]`.

Operand value transforms (`UsipField.type`): `reg` (`rN`; the `{N:!}` template token prints the high-bank `!`;
`base` holds a constant ADDED to the field — `rB1 = rB + 1` of `ld.d/st.d`, `sh = m + 1` of the 16-bit `lsl`, `12 + 8x`
of cell A), `imm` (× `scale` when declared: `addsp`, `lea?`, `ld.d? b10` ×4, `ldslot` k), `simm` (sign-extend to the
total field width, × `scale`: `ld.d/st.d` offset = 4·sext10(s:v9), the bcc48 imm9), `rotimm` (`rot(f,n)`: bit 0 is the
sign), `urot`, `disp` (signed, × `scale`, pc-relative: target = head address + value; for the prefix forms the head is
the packet start), `udisp` (loop end, inclusive), `absaddr` (`base | value`, `base = SEG[A] = A << 26`, `0x78000000` for
the hi(1010) family `lea/lea?`), `acc`, `accw`, `csr` (unused), `csr_ext`, `flag`, `movhi` (the collected bits — V20 =
`i:t1:t0:f12[0]:m:h:rrr:f12[11:1]` for `movhi`, `f12[11:1]` for `movhi_small` — `<< 12`), `offh` (half-word offset:
`f` even → `f`, odd → `f − 0x1001`), `offw` (word offset: `(f & 3) == 3 && f >= 0x800` → `4·sext10(f >> 2)`, else `f`),
`loopn` (`(raw >> 1) + ((raw & 0x1f) != 0)`). The 48-bit constants use a plain 32-bit `imm` field `val` =
`head[13:9] << 27 | hi[12:0] << 14 | lo[13:0]`.

Bank bits: `x` (head/unit bit 8) is the bank of **rB** (destination / data), `m` (bit 13) is the bank of **rA**
(source / base; also the compared register of the 32-bit `b<cond>` and the destination of the 16-bit `movi rA!,
#imm5`), and for op 7 `ss & 2` (head bit 13, field `ss1`) puts **rs1** in the high bank. Templates print them as
`{x:!}`, `{m:!}`, `{ss1:!}`.

Constraints that are not mask/value (`cons` records, evaluated by `cons_ok()`): address windows (`call.abs`, `mov32`
windows), `B != 0` for `sys`, `rA not in {14,15}` for the 16-bit `bz.s/bnz.s`, the near-`b` displacement range, the tail
guards (`setcc_tail`, `tail_not_named16`, `or2_tail`), `field >= n` / `> n`, `field in [..]` on hidden fields (`u9`,
`rA5`, `f12`, `csr`, `lo4`, `mh`, `op`, `A`, `hi12`; large sets as 64-bit membership masks), `even` / `odd`, `any` (up to
three alternatives incl. set membership), `packet_len == n` (stand-alone units; `== 3` for `add32_0eX0_L1`),
`packet_len >= n`, `head_index == n` / `head_pos_ge n`, `ctx:not_ext_of_op67`, the target guards and
`guard:head_not_validated_bs`, and the 16-bit entries whose **mask includes bit 15 = 1** (closers). The context-free
constraints are evaluated by the pairing predicates; the position / length / context constraints are deferred to the
decode of an assignment (a failure falls through to the next entry of the cell), followed by the b.s guard (undo) and
the target guards (`.word`). `kind` values: see `enum usip_kind`.

Context rules (not table entries, see `usip_isa.json structure.context_rules`): `.lo` after a loose `hi(1010)`
syllable, `.ext` (`fX?7` after a `ld/st` whose tail has S = 0), `.be79`, `bz_s_P4`, `slot_S0_R7` / `lea_sp_S0`,
`op8_slot_split`, `sgt_closer_pair` (`4NN7 cc00`), `cells_by_position`, `not_ext_of_op67`. `structure.sys_ops` lists
the `sys`-shape families by tail field (fld 0 `ret`/`jr rB`, 1 `call rB`, 2 `ret?`, 4 `cop/rti/lpexit?/isync?/ieon/
ieoff/sys? #13/idle`) and the F = S = 0 twin; `structure.conditions.bcc48` the 48-bit condition table;
`structure.registers.io_ports` the port map of `ior/iow`.

What the table cannot express (rules of the decoder, documented in `structure.packet`): the group / round-robin
enumeration and its bare-head filter, the explicit candidates (3-unit F' = 0, H H T T, `0e10 3fc0 c000`), the layout
order `(s0, I, Fv, −A, K)` and the tie-break penalties, the late evaluation of the guards, R0/R7, the `5e0d` rule, the
op8 slot split, the forced decode of hi(1010)-shaped heads in 4-unit packets.

## 3. Confidence and what is format-only

* `high`: encoding and operation established by independent checks — the whole control flow (`b<cond>` incl. the
  48/64-bit `b<cond>.l`, `call`, 16-bit branches, `loop` incl. `loop #N`, `call.abs`, the F' = 0 tails), ld/st with
  offset incl. the signed `ld.d/st.d` and the negative half-word / word offsets, the 16-bit ALU, the 32-bit ALU,
  `movi21`, `mov32/add` by formula, `movhi`, the basop/DSP family, mul/div, bit ops, CSR access, port I/O,
  `save/restore`, `nop32`, `cmov r15`, `sne`, `seq`, `slt`, `sgt`, `addsp`, `osl`.
* `medium`: statistically established or with one confirmed example, or sign/width open (`ld.hu?`, `ld.bu?`, `st.h?`,
  `ld.w?` stack slots, far `b`, SP adjustments, `rd!` twins, `st.b?`, `lea?`, `ldslot/stslot`, `mfcsr?`, `ret?`, `jr`,
  `seq?/sle?` (|imm| > 256), `sle`, `ld.d?/st.d?` (b10), `ld.w?/st.w?` (the 0x800-0xeff band), `ld.b?` (f12 = 0),
  `mov32?`, `lea?` (top5 = 8), `mfacc?` (cell C), `add?/st.h?` (cell E), the `idx_*_hi` / `idx_post_*` loads, `bcc48?`,
  `ble.l?`, `bneu.l?`, `bequ.l?`, `movi?` (op b), `bclr?/binv?/bext? rd!`, `lpexit?`, `isync?`, `extu`, `ior?/iow?`).
* `low`: named hypotheses (`clr.a?`, `msu?`, `.osl?`, `.cmp?`, `or.2`, `add.1`, accumulator shifts, `sys?`).
* `format-only`: the pairing is established but not the operation: mnemonics starting with `.` (`.hword`, `.word`,
  `.w48`, `.dsp`, `.alu32`, `.op4imm/.op4i`, `.op7t`, `.bf?`, `.idx?`, `.ctl15/.ctl15.t?`, `.1eX0`, `.6008`,
  `.hi/.lo/.hilo/.ext`, `.fill`, `.st7`, `.op5i?/.op5b10?`, `.op8?/.op8.t?/.opd?`, `.slot?`, `.sub?`, `.sp0?`, …). The
  plugin still groups their units and prints them as data.

Open points that matter for a disassembler: the remaining layout ties; the 16-bit op signatures; the non-canonical
48-bit constants and the split absolute stores (`binv?/bext?`); `ld.w` vs `add` in the op 0 F = S = 1 cell with
`f12 ≡ 0`; `f12 ≡ 2` word offsets; the 0x800-0xeff word-offset band; op d vs op f in `bcc48`; the bit 4 of `loop #N`;
`4028 4002` and the movhi tt = 10 cell; `.idx?` a = 2; `.osl?`; the odd-`.h` alignment penalty; the semantics of `5e0d`.

## 4. ABI (for `regs()`)

`r14 = SP`, `r15 = LR`, arguments `r0-r7` (r0-r3 most used, stack args > r7 at `ldslot #k` = SP + 4k), return `r0`
(`r0:r1` for 64 bits; 64-bit products live in the accumulators `A0-A3`), callee-saved `r8-r10, r12, r13` (+ the
high-bank copies) via `save w` (`w = 2` saves `{r11!,r12!,r13!,r14!}`: four words; `w = 4` saves `{LR, r8}`: two
words), `r11` caller-saved. There is **no classic CSR bank** reachable through op 4: that shape is port I/O
(`ior rB, [rA]` / `iow rB, [rA]`). Extended CSRs `0x01-0x3e` via `mfcsr` and `mtcsr #nn, rA`. There are no flags: all
branches are compare-and-branch (incl. the 48-bit `b<cond>.l rB, #imm9 / rA`).

## 5. Known limitations of the table-driven reading

1. **Ties.** Readings tied on `(s0, I, Fv, −A)` are decided by the assignment key `K`; the decoder sets
   `opex.packet.ambiguous` (a small fraction of the packets, mostly `S S O O` and longer packets where several head/tail
   assignments have the same cost).
2. **Control flow in open packets** (`call`/`b`/`loop`/`b.s` followed by delay-slot ops): when the branch reading
   is not the cheapest one the packet reads as `add`/`st.w`/`st.h`/`movi`. A disassembler that knows the function
   table can prefer the reading whose target is a function start or a packet boundary.
3. **Target guards that cannot be evaluated** (§6): far `b` to another function (and the readings of the packet
   behind it), the open-packet `call.s`, and `loop`/`bnez.d`/register `b<cond>` with a forward target beyond the
   lookahead are read as data or as the plain 16-bit units.

## 6. Target guards: what the plugin knows

The decoder asks the caller through `UsipGuardCtx` (`packet_start`, `function_start`: yes / no / unknown).
`arch_md32.c` answers **packet starts from the stream**: the packet starts decoded earlier in the session (a hash set
in the session state: backward targets, and forward targets of a region decoded before, e.g. after `aa` or on a second
listing) and a scan of the bytes radare2 passes with the op past the current packet (forward targets; radare2 caps the
op bytes at 64, `r_anal_op_set_bytes`), so a forward target farther than 64 bytes is unknown on a first linear pass.
"Same function" is approximated by "reachable in the linear decode" (no function bounds). **Function starts are
unknown**: an arch plugin has no typed access to RAnal (`RArch.user` is an untyped pointer), so no callback is
installed; `UsipGuardCtx.function_start` is the hook for an embedder that has a function table.

When a guard cannot be evaluated the decoder applies a fallback chosen by measurement on the sample the table was
built from (`unverified_ok()` in `usip_decode.c`, by form name and tail distance): the forms whose unverified readings
are right in nearly every case where they compete are read anyway — `call_F0` (function start unknown; with the
tie-break bonus), `b_F0`, `beqz_d` and the immediate `b<cond>` forms with the F' = 0 tail
(`beq/bne/ble/blt/bgtu/bge/bgt_imm8_F0`, forward target beyond the lookahead), the `bcc48_*` / `bcc48_*_64` prefix
forms (forward target beyond the lookahead), `loop_imm_F1S1`, `loop_imm_F0S0` with the tail adjacent and
`loop_imm_F1S0`; the others are treated as a failed guard — `call_s_S0` (only a small fraction of the shapes are
calls), `b_far` (about a fifth of the unverified readings would be wrong), `bnez_d` (the cell is shared with the op C
DSP pairs), `ble_rr_F0`/`blt_rr_F0` (shared with `.ctl15`), `loop_F0` (`movi || mov` pairs), `loop_imm_F0S0` with the
tail at +2. Backward targets are decided by the session (seen = packet start, unseen = not a packet start), never
unverified. An accepted-unverified reading prints a trailing `?` (`call?`, `beqz.d?`, `blt?`, `bne.l?`, `loop#?`),
reports `confidence = medium` and `target_guard = "unverified"` in `opex`; a validated one reports `"validated"`.
