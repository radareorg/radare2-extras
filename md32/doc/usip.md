# uSIP (MD32 family, VLIW packet variant) — ISA table notes for the `usip` CPU mode

Reference for the table format, the constraint semantics and the packet model behind the `usip` CPU mode.  Everything
in it is implemented by `usip_decode.c` (packet model), `tools/gen_usip_tables.py` (table) and `arch_md32.c` (RAnalOp
mapping); see README.md "uSIP mode" for the user-facing description.  Files:

| file | what |
|---|---|
| `isa/usip_isa.json` | the machine-readable table: `meta`, `structure` (packet model incl. the layout order, the K-tie cascade, the prefix, grammar and rename rules, registers, CSRs, system ops, I/O ports, conditions incl. the 48-bit condition table and the S0F1 tail variants, displacement and immediate formulas, field types, context rules) and the ORDERED list `forms` |
| `usip_opcodes.h` | the same forms as a C table (`UsipOpcode usip_opcodes[]`), generated by `tools/gen_usip_tables.py`, plus `usip_never_tail[]`, `usip_never_head_with_tail[]`, `usip_c48_table[]`, `usip_br0_cells[]` / `usip_br0_cells_weak[]`, `usip_c48sym_table[]`, `usip_value_sets[]` and the `rename_from` lists |
| `usip_decode.c` | the packet decoder (`parse_group`, `group_parses`, `decode_asg`, `score`, `fviol`, `parse_packet`, `apply_renames`, `decide_ties`) |

## 1. The packet model

The earlier `usip_decode()` read one 16-bit halfword and, when bit 15 was 0, paired it with the next halfword. That is
wrong in general: **the unit is the 16-bit halfword and the instruction stream is a VLIW packet stream.**

1. **Unit scan.** Read halfwords (big-endian) from the packet start. A packet = consecutive units up to and
   including the first unit with **bit 15 = 1** (max 8 units). Packets start at `addr % 4 == 2` as often as at
   `addr % 4 == 0`: never assume 32-bit words. Branch targets are packet starts.
2. **Heads and tails.** Inside a packet, a unit with bit 15 = 0 is either a *head* (first unit of an instruction) or
   a *tail* (second/third unit of a 32/48-bit instruction). Instructions are **head + 0, 1 or 2 tails**, 16/32/48 bits
   (64 bits only for the `bcc64` prefix forms: head + `1e0d` + U1 + T). A head without a tail is a 16-bit op "with the
   packet still open" (its bit 15 is 0 but it is decoded like the bit-15 = 1 form; most 16-bit entries of the table mask
   bit 15 out, the stand-alone *closer* forms keep it).
3. **Prefix forms.** Before anything else, if the packet opens with the three (four) units of a `bcc48` (`bcc64`) entry
   (`USIP_F_PREFIX`: U0 op b-f with F = 1 (F = 0 + `1e0d` for the 64-bit twin), U1 `[0][1][m'h'][rrr'x'][00000000]`, T
   `[S][1][00][d12]`) AND the target `packet start + 2·sext12(d12)` is a packet start of the same function (≠ the packet
   itself), those units are ONE instruction and the rest of the packet is its delay slot (parsed as an independent packet
   without control flow). A failing guard means the entry is simply not taken (normal layout, never `.word`). The absolute
   `call.abs/b.abs` prefix (`x008 + hi + lo`, rule R) is unchanged. `5e0d` as U0 (`bgt.l r0, #255`) and `1e0d` as the
   bcc64 extension unit are matched here, before the never-tail rule of item 4.
4. **Layout (head/tail pairing).** Tails are not necessarily adjacent to their head: the packet is *heads first,
   then tails*, and the tails are dealt **round-robin** among the heads that take tails, in head order (`S S O O` =
   two 32-bit instructions interleaved). A packet may also be a sequence of *groups*, each laid out that way
   (one-instruction groups = contiguous layout: `b dest ‖ delay-slot ops`). No bit selects the layout. The decoder
   enumerates every group split and every head/tail assignment allowed by the table (a head may take a tail iff some
   non-context, non-rename form matches head+tail; a head may stand alone unless it is in `structure.packet.must_pair`;
   `ret/save/restore` never take tails; **the units of `usip_never_tail[]` (`5e0d`) are never a tail and the heads of
   `usip_never_head_with_tail[]` (`5e0d`, `1e0d`) never take one**; **a 48-bit op 0 head also takes `hi + lo` when
   `head[13:9]:hi[12:0]:lo[13:0]` is one of the values of `usip_c48_table[]`**, the non-canonical 48-bit constants
   admitted by value — in the partial head:hi admission some table value must share the upper 18 bits), discards,
   inside a group, the assignments with more bare heads that have no named 16-bit reading, adds the explicit candidates
   (`[head][op16][F' = 0 tail]` for 3 units — not for a head that never takes a tail —, **H H T T** =
   `[h0][h1][t0 S=0][t1 S=1]` with two named ld/st for 4 units, also with tt = 11 tails (`ld.bu` / `st.b`) and the
   bit-field pair `[op 7][op 7][tt = 01 S = 0][tt = 01 S = 1]`) and ranks the readings with the **prior-free total
   order** (`structure.packet.layout_order`): `(s0, I, Fv, −A, K)` ascending, where `s0` = unknown units (kind `other`:
   1 per unit; kind `fmt`: 1 per instruction) + the tie-break penalties of `structure.packet.tie_breaks` (R7 credit, O
   syllables, loose `4000`, alignment except `f12 ≡ 3 ≥ 0xf00` and except `f12 ≡ 2` in the H H T T / H H T T C layout
   (P2W), the add relabel, 1dX6, `.hi/.hilo`, the fam48 r14/r15 destination, the store-of-immediate triples, the
   identical-units rule of 4-unit packets, the mfcsr pair, the validated-guard −0.5, **callin**: +1.5 for a relative
   `call` whose target is strictly inside a known function, **P2H**: the odd half-word offset is not penalised in
   H H T T / H H T T C except `f12 = 0x001` with base sp, **R-lr16**: +0.5 for a 16-bit `ld/st.b|bu|h r15, [rA]` in a
   2-unit packet, **R-align48**: +0.5 for a formed 48-bit hi(1010) ld/st trio whose address is misaligned,
   **R-c48sym**: +0.5 for a reading that leaves a 48-bit-family head without tails while a later free hi(1010) + lo of
   the packet encode an address of `usip_c48sym_table[]`), `I` = number of instructions, `Fv` = heads with a tail
   whose adjacency contradicts the **F pattern** (head F = 0 and next unit bit 14 = 1 ⇒ adjacent tail, otherwise
   deferred), `−A` = minus the number of adjacent tails, `K` = the sorted tuple of `(head index, (tail indices…))`
   (smallest first). Readings tied on `(s0, I, Fv, −A)` go through the **K-tie cascade** (item 12) and, when it does
   not decide, are the **ambiguous** packets (K decides) unless the tied readings are identical. No learned prior and
   no group count take part. Rule **R0**: the final closer (bit 15 = 1) may be a one-unit group of its own even when it
   has no named 16-bit reading. Rule **R7**: a bare first-slot unit with bit 15 = 0 of the slot family (or of the `lea?`
   shape with rA ≠ r14 when no other instruction of the packet has a tail) counts as a named unit when every other
   instruction of the packet is named, and is printed through the context forms `ldslot_S0`/`stslot_S0`/`lea_sp_S0`.
   When no group parse exists a greedy fallback pairs each head with the next free unit if some form matches.
5. **Slot 0.** Only the first unit of a packet can be control flow (branches, `call/b`, `loop`, `loop #N`,
   `bcc48/bcc64`, 16-bit branches incl. `call.s` with bit 15 = 0, `beqz.d/bnez.d` with F = S = 0, `call.abs/b.abs`,
   the `b<cond>.d` with the `[0][1][tt]` tail at +2: the S0F1 cells, the `b<cond>.d` with head F = 0 of the R-br0
   cells (tail `[0][1][tt]` at +1 or +2, `USIP_C_BR0_CELLS`), `ret.s.d`, `loop.b1?`, `bz.s` with bit 3 = 0); forms
   flagged `USIP_F_SLOT0` must not be matched elsewhere. The 32-bit `ret` (`40ff c000`), `ret?`, `jr rB`, `call rB` and
   the `sys` twins with F = S = 0 are NOT slot-0 forms. Tail adjacency of the control forms (`USIP_F_ADJCTRL`: +1
   with S = 1 or +2 with S = 0; `USIP_F_ADJ2`: exactly +2 for the F' = 0 control tails, for the S0F1 branch tails AND
   for `loop #N` with F = 1, S = 0 — at +1 that one is two 16-bit ops, not `.word`; `loop_F0` also at +2 with S = 1).
   **Target guards**
   (`cons = "guard:target_*"`): for 32-bit forms evaluated AFTER the mask match, a failure makes the pair `.word` (no
   fall-through; the op C compare-and-branch cell, `bnez.d` with F = S = 0, leaves a `.dsp` pair: the pair is unnamed
   data either way, the name is the only difference) unless the entry carries `USIP_F_GUARDFT` (the F = S = 0
   `b<cond>.d` cells, `bne.d #-1`, the R-br0 cells: the next entry of the cell is tried and, when none is left, the two
   units are 16-bit ops — R-tgt, item 13: the known target is a filter, never a partition); for the 16-bit `call_s_S0`
   and the open `b.s` (`b_s_open`: a packet start of the same function or a function start) a failure falls through;
   for the prefix forms a failure means "not taken". The near `b` (`b_near`) needs a packet start of any function of
   the image or a function start (`guard:target_packet_start_any_or_function_start`), the hardware loops with the
   F' = 1 tail (`loop`, `loop.b1?`, their `?ss=N` twins) a packet start of the same function.
6. **Deferred tails and undo.** `USIP_F_ADJDEF` (`st.h` with the F' = 0 tail, R-st1h): the tail must be at +2 or
   farther; an adjacent tail undoes the pair into two 16-bit ops. `guard:head_not_validated_bs`: in the first slot,
   when the head is a 16-bit `b.s` shape (`5cX1/7cX1`, not m = 0 with d6 = 0) whose target is a packet start of the same
   function, the pair is undone (the `b.s` wins). `USIP_F_ADJ1` (immediate set-on-compare, `add_FS12`, `seq/slt` of
   op 6): a farther tail undoes the pair. `USIP_F_ADJ2` on a ld/st entry (`mem_ld_b_t4_F1S0`, `mem_st_h_t6_F1S0`,
   R-op1fs: the F ≠ S `ld.b` / `st.h` of op 1): the tail must be exactly at +2; at any other distance the pair is
   undone into two 16-bit ops (not `.word`).
7. **Position selectors.** Constraints `head_index == n` / `head_pos_ge n` (unit index of the head inside the packet)
   and `packet_len >= n` select the identical-bit cells by position: `mfacc_q_C_k2` (k ≥ 2), `cellE_st_h_q_k1` /
   `cellE_add_q_k2`; `ld_w16_A_k0` (k = 0) and `lsl16_F1_S0_k1_q` (k ≥ 1) are post-layout renames (item 11). Entries
   whose deferred constraints fail FALL THROUGH to the next entry of the same cell. `ctx:not_ext_of_op67`
   (`add_FS1_rot12_odd`) needs the first unit of the packet. `ldslot_S0_m1` / `stslot_S0_m1` (R-slotm1: the m = 1
   slots of op 4/8/c, k ≥ 32) are R7 forms that also need `ctx:rest_named_no_q` (every other instruction named, none
   with a `?`).
8. **Context forms (`USIP_F_CTX`).** `bz_s_P4`, `bz_s_P5` (R-bzs5: a first-slot `4X?5/6X?5` unit, rA not sp/LR,
   whose best reading is a bare unnamed unit is `bz.s rA, dest` with the rest of the packet as its delay slot:
   unconditionally in a 2-unit packet, in a longer one only with the target validated as a packet start of the same
   function), `ldslot_S0/stslot_S0/lea_sp_S0` and the m = 1 twins (R7 / R-slotm1), `ldslot_split/stslot_split` (the
   two halves of an `.op8?`/`.op8.t?` pair of slot-family units, context rule `op8_slot_split`), the `hhtt_*` ld/st
   forms with F ≠ S and the `b111_*` ld.bu / st.b forms with F ≠ S or F = S = 0 (only inside the H H T T candidate:
   `USIP_F_HHTT`, `ctx:b111_layout`), the `b111_*_F1S1` forms (`USIP_F_B111`: the 2-unit head + tail packet with a
   named 16-bit tail, and H H T T), the bit-field pair `bfpair_*` (`ctx:bfpair`, `bf_valid`), the `f0ctx` group
   `hhttF0_*` / `rf0d_*` (`USIP_F_F0CTX`, `ctx:hhtt_second_head` / `ctx:f0d_triple`: tried when the op 0 +
   `[S][0][01|10]` pair at +2 reads `.word`; after an `rf0d_*` reading the unit between head and tail is re-read with
   the first-slot 16-bit cell when that gives a named, non-control op that does not write r14: context rule
   `f0d_middle_unit`) and `hi1010_loose` (`.hi`): a lone unit with bits 12:9 = 1010 is `.hi` (and the next `.hword`
   `.lo`) only when a head of the 48-bit family precedes it in the packet (context rule `hi_lo_fam_before`); otherwise
   it is an ordinary 16-bit head with base/source r10 (**H1**: a hi(1010)-shaped unit is a `hi` syllable only inside a
   formed 48-bit instruction; the table has no `not_hi1010` constraints and no `.hi/.hilo` pair entries, and the
   parser no longer forces the hi(1010) decode of such heads in 4-unit packets).
9. **Delay slot = the rest of the packet.** When the control instruction does not close the packet (`call`/`b` with
   an S = 0 tail, `b<cond>.d` incl. the S0F1 forms, `b<cond>.l` with S = 0 on T, `ret.d`, `b.s` with bit 15 = 0,
   `call rB`, `call.abs`), every other unit of the packet executes before the transfer (on both paths). For radare2 this
   means `op->delay` = number of remaining ops in the packet, and the branch instruction's `size` covers only its own
   units while the fall-through address of the packet is the next packet.
10. **Hardware loops.** `loop rX, last=pc+disp12`, `loop #N, last=pc+disp12` (`USIP_A_LOOPN`: N = `((rrr:x:B) >> 1)
    + [x:B ≠ 0]`), `loop.b1? rX, last=…` (the head with B = 1: the meaning of that bit is open) and the `?ss=N` twins
    (`loop r<rrr>?ss=N`, `loop.b1? r<rrr>?ss=N` for ss ≥ 2): `last` is the address of the LAST instruction of the body
    (inclusive); the body is the following 1-16 instructions; `last` must be a packet start of the same function and
    ≠ pc. `de0d` (`nop.ctl` with S = 1) closes most hardware-loop bodies.
11. **Post-layout renames (`USIP_F_RENAME`).** Thirty-one entries (`nop_ctl`, `lsl16_S0`, `lsl16_F1_c`,
    `lsl16_F1_S0_k1_q`, `sext16_F1_c`, `sext16_F1_S0_q`, `zext16_F1_c`, `zext16_F1_S0_q`, `addi32_cop`, `ld_w16_A_k0`,
    `x1e0_ld_w_q`, `x1e0_ld_h_q`, `x1e0_ld_hu_q`, `op7e_0_bset_r`, `op7e_6_bext_r`, `ldF0_q_t1_adj`, `ldF0_q_t2_adj`,
    `ld_h_q_Fp0`, `ld_hu_q_Fp0`, `x3eX0_q`, the BF_SEL cells `bfsel_fup`, `bfsel_fup_q`, `bfsel_fxtu`, `bfsel_fxtu_q`,
    `bfsel_fxts_q` from `.bf?` with `ctx:bf_dst_not_written` — no other WAW-kind instruction of the packet writes
    rB(!x) —, `negq_ld_w_c1/c3`, `negq_st_w_c1/c3` (`ld.w?` / `st.w?`), `spfix_add_sp` (from `ld.w`), `spfix_sub_sp`
    (from `.ldF0?` / `ld.h?`)) are NEVER used while pairing or scoring (the layout is decided with the
    underlying reading: `.ctl15`/`.hword`, `.sub?`, `.1eX0`, `.word`, `.7e`, `mov32`/`add`). Once the layout is
    decided, for each instruction the rename entries of its width are tried in table order: mask over the gathered
    units, `rename_from` containing the current reading (a mnemonic, or `@kind` for every reading of that kind), the
    other constraints (`head_pos_ge 1`, `tail_adjacent == true/false`, `ctx:cop_rA_in_packet`,
    `ctx:not_c48_lo_follows`, `u16 in [...]`) → the instruction takes the entry's mnemonic / kind / format; the score
    is untouched.
12. **K-tie cascade.** For each packet whose readings tied on `(s0, I, Fv, −A)`: `dedup` (identical multisets of
    instruction texts → the K reading), `nowaw` (exactly one reading without a double register write → chosen; all
    with one → no decision), `du2` (a differential use-definition score over a window of eight packets before and
    after the packet, decision margin 1: only the registers whose role differs between the tied readings score — in
    the forward direction a use, an argument, a dead value or a clobber of the register; in the backward direction a
    definition, a return value, a live or a clobbered register); the chosen reading replaces the K reading. A fourth
    step, a vote of the debug line table over other packets of the same source line, is not reproducible from the
    bytes and is left to K. A decoder without any function context reproduces the bare K key; the cascade is a
    tie-break improvement, not an admission rule. §7 describes what the plugin can see.
13. **Address views (R-img) and the target filter (R-tgt).** Every function is validated with the packet starts,
    function starts and ranges of its own image: a function table that holds two overlapping copies of the same code
    (a routine mapped twice, each copy with its own ranges) must carry the image, or a merged table validates targets
    of the other copy and rejects branches with the wrong function limits. A disassembler that works on one image at
    a time has a single view by construction, so the plugin has nothing to do for R-img. R-tgt: a known target is a
    filter, never a partition. The plugin asks the caller for packet starts and function starts (§6); a known target
    that is not one rejects the reading (fall-through to the next entry of the cell for the `USIP_F_GUARDFT` entries,
    the next 16-bit entry for the open `b.s`, `.word` for the near `b` and the loops), an unknown one keeps the
    reading unverified for the forms whose guard is a validation filter.

Operand fields are given as bit ranges over the big-endian concatenation of the instruction's units (bit `width-1`
= bit 15 of the head): 32-bit forms = head bits 31..16, tail 15..0; 48-bit = head 47..32, hi 31..16, lo 15..0; 64-bit =
head 63..48, ext 47..32, U1 31..16, T 15..0. When the units are not adjacent in memory the plugin gathers them (head,
then its tails in round-robin order) before applying mask/value.

## 2. The table

`tools/gen_usip_tables.py` emits every field referenced by the format string or by a constraint (`nfields` >=
`nargs`), the constraints as structured `UsipCons` records (op, field indices, values), the `rename_from` lists of the
rename entries, the indices of the context-only forms (`USIP_FORM_*`, incl. `hi1010_loose`) and the auxiliary tables
of the ISA description (`usip_must_pair`, `usip_sys_fld4[16]`, `usip_cond_bcc48[5][4]`, `usip_csr_ext[64]`,
`usip_kind_names[]`, `usip_save_set[8]`, `usip_never_tail[]`, `usip_never_head_with_tail[]`, `usip_c48_table[]`,
`usip_br0_cells[]` / `usip_br0_cells_weak[]` (`UsipBr0Cell`: op, tt, class, distance), the sorted `usip_c48sym_table[]`,
`usip_value_sets[]`); the generated header is `usip_opcodes.h` and regenerating it is byte-identical. Form names are
sanitised into C identifiers for the `USIP_FORM_*` indices. Limits: `USIP_MAXRANGES 8` (the movhi V20
field collects 8 ranges), `USIP_MAXFIELDS 12`, `USIP_MAXCONS 8`, `USIP_MAXVALS 12` (the `fup` cell set); the 16-bit
forms may only use `packet_len` 1/2, `packet_len_ge` 2, `head_index` 0 and `head_pos_ge` 2 (the 16-bit match cache is
keyed by those classes), except the rename and the context-only entries, which are evaluated with the exact head
index after the layout. The constraint ops `tail_adjacent` (`USIP_C_TAIL_ADJACENT`, `vals[0]` = 0/1; also the `any`
sub-operation `USIP_ANY_TAIL_ADJACENT` with field `USIP_NOFIELD`), `ieee_short` (`USIP_C_IEEE_SHORT`, `vals[0]` =
significant digits), the membership in the 48-bit value table (`USIP_C_IN_C48TAB`, emitted for an `in` set equal to
the table), `br0_cells` / `br0_cells_live` (`USIP_C_BR0_CELLS` / `USIP_C_BR0_CELLS_LIVE`: field = rB, `vals[0]` = a
cell mask, `USIP_BR0_BIT(class, dist)`), `bf_valid` (`USIP_C_BF_VALID`, fields w / pos), the guards `tail_named16`
(`USIP_C_GUARD_TAIL_NAMED16`) and `target_packet_start_any_or_function_start` (`USIP_C_GUARD_TARGET_PK_ANY_OR_FN`),
the value sets too large for `vals` (`USIP_C_IN_SET` / `USIP_C_NOTIN_SET` into `usip_value_sets[]`), the `any`
sub-operations `USIP_ANY_PACKET_LEN`, `USIP_ANY_GUARD` (`enum usip_guard_id`), `USIP_ANY_RANGE` (`lo | hi << 16`) and
`USIP_ANY_BR0_CELLS` / `USIP_ANY_BR0_CELLS_LIVE`, and the context conditions `USIP_CTX_COP_RA_IN_PACKET` /
`USIP_CTX_NOT_C48_LO_FOLLOWS` / `USIP_CTX_B111_LAYOUT` … `USIP_CTX_REST_NAMED_NO_Q`, are evaluated by the decoder with
the packet context.

`usip_opcodes[]` is ordered: the first entry of the right width whose `(units & mask) == value`, whose `flags`
allow the slot, and whose `cons` holds is the reading (entries with `USIP_F_RENAME` are excluded from that matching:
item 1.11). Fields of each entry: `name` (mnemonic), `form` (stable id = `usip_isa.json` `forms[].name`),
`value/mask`, `width/nunits` (16/32/48/64), `flags` (`USIP_F_SLOT0`, `NOTSLOT0`, `CTX`, `DELAY`, `ADJ1`, `ADJCTRL`,
`NAMED`, `NOTAIL`, `ADJ2`, `UNKNOWN16`, `ADJDEF`, `PREFIX`, `RENAME`, `HHTT`, `GUARDFT`, `B111`, `F0CTX`; a `ut32`),
`kind`, `conf`, `fmt` + `fields[]`
(operand template and bit fields, up to 8 ranges), `cons[]`, `rename_from` / `nrename_from` (the readings a rename
entry may replace).

Operand value transforms (`UsipField.type`): `reg` (`rN`; the `{N:!}` template token prints the high-bank `!`;
`base` holds a constant ADDED to the field — `rB1 = rB + 1` of `ld.d/st.d`, `sh = m + 1` of the 16-bit `lsl`, `12 + 8x`
of cell A), `imm` (× `scale` when declared: `addsp`, `lea?`, `ld.d? b10` ×4, `ldslot` k), `simm` (sign-extend to the
total field width, × `scale`: `ld.d/st.d` offset = 4·sext10(s:v9), the bcc48 imm9), `rotimm` (`rot(f,n)`: bit 0 is the
sign), `urot`, `disp` (signed, × `scale`, pc-relative: target = head address + value; for the prefix forms the head is
the packet start), `udisp` (loop end, inclusive), `absaddr` (`base | value`, `base = SEG[A] = A << 26`, `0x78000000` for
the hi(1010) family `lea/lea?`), `acc`, `accw`, `csr` (unused), `csr_ext`, `flag`, `movhi` (the collected bits — V20 =
`i:t1:t0:f12[0]:m:h:rrr:f12[11:1]` for `movhi`/`movhi_tt10_short`, `f12[11:1]` for `movhi_small` — `<< 12`), `offh`
(half-word offset: `f` even → `f`, odd → `f − 0x1001`), `offw` (W14, a 14-bit word displacement: `(f & 3) == 2` →
`0x1000 + (f & ~3)`; `(f & 3) == 3 && f >= 0x800` → `4·sext10(f >> 2)`; else `f`), `offb` (the byte displacement of
`ld.b/ld.bu/st.b`: `sext12(f[0] : f[10:1] : f[11])`, bit 11 of the field is bit 0 of the displacement and bit 0 the
sign; printed with its sign), `loopn` (`(raw >> 1) + ((raw & 0x1f) != 0)`). An immediate glued to a letter or to `=`
(the accumulator index `A{k}`, the loop `?ss=N`, `save w=N`) is printed in decimal. The 48-bit constants use a plain
32-bit `imm` field `val` =
`head[13:9] << 27 | hi[12:0] << 14 | lo[13:0]`. The bit-field position `pos` of `fxtu/fxts/fup` is a plain `imm`
whose ranges `[0,0],[4,1]` implement `rotr5(p)`.

Bank bits: `x` (head/unit bit 8) is the bank of **rB** (destination / data), `m` (bit 13) is the bank of **rA**
(source / base; also the compared register of the 32-bit `b<cond>` and the destination of the 16-bit `movi rA!,
#imm5`), and for op 7 `ss & 2` (head bit 13, field `ss1`) puts **rs1** in the high bank (also in `bset/bext rd, rs1,
rB` and the bit-field family). Templates print them as `{x:!}`, `{m:!}`, `{ss1:!}`.

Constraints that are not mask/value (`cons` records, evaluated by `cons_ok()`): address windows (`call.abs`, `mov32`

## 4. ABI (for `regs()`)

`r14 = SP`, `r15 = LR`, arguments `r0-r7` (r0-r3 most used, stack args > r7 at `ldslot #k` = SP + 4k), return `r0`
(`r0:r1` for 64 bits; 64-bit products live in the accumulators `A0-A3`), callee-saved `r8-r10, r12, r13` (+ the
high-bank copies) via `save w` (`w = 2` saves `{r11!,r12!,r13!,r14!}`: four words; `w = 4` saves `{LR, r8}`: two
words), `r11` caller-saved. There is **no classic CSR bank** reachable through op 4: that shape is port I/O
(`ior rB, [rA]` / `iow rB, [rA]`). Extended CSRs `0x01-0x3e` via `mfcsr` and `mtcsr #nn, rA`. There are no flags: all
branches are compare-and-branch (incl. the 48-bit `b<cond>.l rB, #imm9 / rA`).

## 5. Known limitations of the table-driven reading

1. **Ties.** Readings tied on `(s0, I, Fv, −A)` go through the K-tie cascade (§1.12, §7); what it cannot decide is
   left to the assignment key `K` and flagged `opex.packet.ambiguous` (a small fraction of the packets, mostly `S S O O`
   and longer packets where several head/tail assignments have the same cost). The `du2` step sees a shorter context
   than a scan of the whole function would give (§7), so a few of its decisions can differ from those of a decoder
   that has the function in hand.
2. **Control flow in open packets** (`call`/`b`/`loop`/`b.s` followed by delay-slot ops): when the branch reading
   is not the cheapest one the packet reads as `add`/`st.w`/`st.h`/`movi`. A disassembler that knows the function
   table can prefer the reading whose target is a function start or a packet boundary, and can answer the `callin`
   tie-break (a relative `call` into the middle of a function, §6).
3. **Target guards that cannot be evaluated** (§6): far `b` to another function or beyond the lookahead (and the
   readings of the packet behind it), the open-packet `call.s`, and `loop`/`bnez.d`/register `b<cond>`, the
   `b<cond>.d` S0F1 and register cells and the `bz.s` of packets longer than two units with a forward target beyond
   the lookahead are read as data or as the plain 16-bit units.

## 6. Target guards: what the plugin knows

The decoder asks the caller through `UsipGuardCtx` (`packet_start`, `packet_start_any`, `function_start`,
`inside_function`: yes / no / unknown). `arch_md32.c` answers **packet starts from the stream**: the packet starts
decoded earlier in the session (a hash set in the session state: backward targets, and forward targets of a region
decoded before, e.g. after `aa` or on a second listing) and a scan of the bytes radare2 passes with the op past the
current packet (forward targets; radare2 caps the op bytes at 64, `r_anal_op_set_bytes`), so a forward target farther
than 64 bytes is unknown on a first linear pass. "Same function" is approximated by "reachable in the linear decode"
(no function bounds): a backward target below the lowest packet start decoded in the session (`lo_seen`) is unknown
(another function, or code never listed), one at or above it that was not seen as a packet start is not one. A
definite "not a packet start" rejects the reading even for the guards that also admit a function start: a target the
caller could look at that is not a packet start cannot be a function start either. `packet_start_any` is not
installed (the session's packet starts stand in).
**Function starts are unknown**: an arch plugin has no typed access to RAnal (`RArch.user` is an untyped pointer), so
neither `function_start` nor `inside_function` (the `callin` tie-break: a relative `call` whose target lies strictly
inside a known function pays the out-of-boundary penalty) is installed; both are the hooks for an embedder that has a
function table.

When a guard cannot be evaluated the decoder applies a fallback chosen by measurement on the sample the table was
built from (`unverified_ok()` in `usip_decode.c`, by form name, tail distance, head/tail bits and the direction of
the target): the forms whose
unverified readings are right in nearly every case where they compete are read anyway — `call_F0` (function start
unknown; with the tie-break bonus), `b_F0`, `beqz_d` and the immediate `b<cond>` forms with the F' = 0 tail
(`beq/bne/ble/blt/bgtu/bge/bgt_imm8_F0`, forward target beyond the lookahead), the `bcc48_*` / `bcc48_*_64` prefix
forms (forward target beyond the lookahead), `loop_imm_F1S1`, `loop_imm_F0S0` with the tail adjacent,
`loop_imm_F1S0`, `loop_F0` when the head has F = 1 and the S = 1 tail sits at +2, and the S0F1 cells
`bne/blt/bgeu/bgtu/bge_imm8_s0f1`, `beqz/bnez_s0f1` and `bleu_rr_s0f1`, and the forms whose guard is a validation
filter (`b_s_open`, `b_near`, `loop` / `loop_ssq` / `loop_b1_q` / `loop_b1_q_ssq` with the F' = 1 tail, the F = S = 0
`b<cond>.d` cells, `bne_d_m1` and the R-br0 `*_f0s0` cells: they were read without a guard before the filter existed,
so an unknown target keeps the reading, the conditional ones only forward); the others are treated as a failed guard —
`call_s_S0` (only a small fraction of the shapes are calls), `b_far` (about a fifth of the unverified readings would
be wrong), `bnez_d` of the F = S = 0 cell (shared with the op C DSP pairs), `ble_rr_F0`/`blt_rr_F0` (shared with
`.ctl15`), the other `loop_F0` tails (`movi || mov` pairs), `loop_imm_F0S0` with the tail at +2, the S0F1 cells
`beq/ble/bgt_imm8_s0f1`, the op 8 S0F1 cells and the op d S0F1 register cells. Backward targets inside the decoded
region are decided by the session (seen = packet start, unseen = not a packet start); below it they are unknown:
unverified for `call`, `b` and `b.s`, never for a conditional branch (a conditional branch does not leave its
function). An accepted-unverified reading prints a trailing `?` (`call?`, `beqz.d?`, `blt?`, `bne.l?`, `loop#?`,
`bne.d?`, `b.s?`, `loop?`), reports `confidence = medium` and `target_guard = "unverified"` in `opex`; a validated
one reports `"validated"`. A 32-bit pair whose target guard failed is `.word`, except the op C compare-and-branch
cell (`bnez.d` with F = S = 0), whose failed pair keeps the DSP shape and is printed `.dsp 0x…` (unnamed data either
way), and the `USIP_F_GUARDFT` entries, whose failed guard falls through to the next entry of the cell (two 16-bit
ops when none is left).

## 7. The K-tie cascade in the plugin

`usip_decode_packet` runs the cascade of §1.12 on every packet whose readings tied on `(s0, I, Fv, −A)` (`cascade()`
in `usip_decode.c`: `decide_ties`, `regs_of`, `du2_scores`):

* **`dedup`** and **`nowaw`** only need the tied readings of the packet itself: the instruction texts (without the
  unverified `?`) and the registers each instruction writes and reads are derived from the text (`rN`/`rN!`/`sp`/`LR`
  tokens, the base of `[rA]+` as a destination, the first operand as the destination when it is a register or a pair,
  the read-modify-write forms, stores and system ops reading everything).
* **`du2`** needs the neighbouring packets. The decoder asks the caller for them through `UsipGuardCtx.packet_at`
  (the packet that ends at an address: the backward context; the packet that starts at an address: the forward
  context) and `branch_target` (the join points). `arch_md32.c` supplies the packets decoded earlier in the session
  (their final readings, from the packet cache) and the **first-pass readings** of the packets that follow inside the
  bytes at hand (decoded with `USIP_GUARD_NO_CASCADE`, so a context packet never runs its own cascade), plus the
  targets of every branch decoded so far. Approximations versus a scan of the whole function with first-pass
  readings: the forward window ends at the 64 bytes radare2 passes (the cascade would look eight packets ahead), the
  backward packets are already-cascaded readings, the join points only include the branches seen so far, and an
  exhausted window is "no event" where a scan that knows the function start would report an argument / undefined
  register. `dedup` and `nowaw` do not depend on the context; a few `du2` decisions do, and a tie `du2` cannot decide
  with the shorter context is left to K (flagged ambiguous).
* `opex.packet.tiebreak` reports `dedup` / `nowaw` / `du2` for a packet decided by the cascade;
  `opex.packet.ambiguous` is true only for the ties the cascade could not decide (K decides them).
* A packet read by the `bz_s_P5` rule parses the rest of the packet as an independent packet: the ties of that parse
  are the ones the cascade sees, and the rule is applied again to the reading the cascade chooses.
